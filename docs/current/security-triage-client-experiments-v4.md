优先使用独立 Linux 虚拟机或另一台实验主机运行 Wazuh；使用者电脑运行客户端和现有 TeleAgent。可以在同一物理电脑模拟，但平台与客户端账号分离，禁止共享原始数据目录、服务端数据库或导入凭据给客户端。

Wazuh 是本项目选择的技术栈，不预设学校已经安装。项目交付参考平台的部署、模块、规则、索引与只读角色配置；应用场景可使用该部署，也可接入有相应能力的现有平台。演示区分“参考部署提供”“特定用例额外启用”和“实际接入方尚未提供”的能力，不能把实验管理员的权限算入日常客户端接入条件。类似平台暂只有内部适配契约，首版不声明第二平台兼容。

| 角色 | 可以接触的材料 | 不进入运行客户端的材料 |
|---|---|---|
| 平台准备者 | 安装与导入配置、原始样本、实验管理员凭据 | 管理员凭据、直接数据库与服务器文件访问 |
| 客户端使用者 | 受限账号、可见告警、实际获准清单、自己的案件 | 评估答案、准备目录、不可见设备数据 |
| 评估者 | 冻结输入与输出、独立标签、人工核验依据 | 不把答案、攻击者角色标签注入普通证据 |

若同一人承担多个角色，运行过程仍用不同凭据、目录和配置，验证产物注明角色切换。学校或实验平台不为客户端新增自研取证服务。

## B. 数据与环境选择

### B.1 四类验证路径

| 路径 | 环境与输入 | 能证明什么 | 不能证明什么 |
|---|---|---|---|
| E1 客户端功能回归 | 受控 Wazuh 响应桩、合成字段、预设分页和错误 | 案件、范围、版本、状态与界面遵守设计 | 真实 Wazuh 兼容、真实模型质量 |
| E2 已有告警接入 | 隔离 Wazuh 的独立实验索引，导入 AIT-ADS 选定片段，客户端只读 | 真查询、告警投影、案件与证据、受限访问 | 本机原始检测召回率、原生清单采集 |
| E3 原生平台补充 | 小型实验主机的原生 Agent，已登记的认证、FIM 或 Syscollector 配置 | 对应模块真实上报、字段、新鲜度与查询路径 | 全校覆盖、任意主机取证和未启用模块 |
| E4 TeleAgent 分层集成 | 先合成文本与最小委派回传，再接专用调查、两类 MCP、E2/E3 受限查询和三入口 | 每一层实际通过的连接、Agent 分支行为、来源绑定与结果投递 | 从前一层通过自动推出下一层完成 |

P0 的数据最低要求是 E2 告警及其可追溯内容；清单、FIM、漏洞和 SCA 不作为所有演示的隐含前提。为了展示某个可选工具，需要在 E3 或真实授权环境中取得相应材料，并说明额外配置。

### B.2 公开数据使用

优先使用 AIT Alert Data Set 的一个场景、小段连续时间。它本身已有 Wazuh、Suricata 等告警，导入独立实验索引，不送入本机 Wazuh 假装重新检测。发布者提供攻击阶段时间标注，不能直接作为每条告警的恶意或良性答案。[AIT-ADS](https://zenodo.org/records/8263181)

需要同场景原文追溯时才增加 AIT Log Data Set V2.0 的必要片段，并先核对来源、主机、时间和原始行号对应。数据集模拟小型企业环境，不能称为高校现场数据。[AIT-LDS](https://zenodo.org/records/5789064)

Windows 安全事件或其他来源仅在选定用例需要时补充，先检查实际事件和字段；不以操作系统名称推断含有认证成功或失败记录。CIC、PCAP 和更多厂商不是本轮必需数据。

不把 AIT 标签文件、攻击脚本、答案目录名或“攻击者主机”属性提供给 Agent。授权实验说明等在真实应用中可获得的业务信息可以作为输入，但需标明来源，不能用数据集真值伪装成业务授权记录。

### B.3 数据准备清单

每次实验记录 dataset/scenario/run 标识、来源版本、文件校验值、所选时间段、映射版本、Wazuh 与规则版本、导入路径、角色权限和预期可见范围。源数据只读保存，实验产物独立存放。

同私网 IP 在不同数据集、场景中不自动视为同一主机；用户、主机与日志观察者保留身份范围。未经核对的跨数据集关联只作为合成测试，不作为真实攻击链。

已有告警导入后保存源 ID、实验索引 ID 和映射关系。已导入记录与平台新生成告警分别标识，重复导入不增加同一实验记录；原始日志重新检测生成新告警时，不继承“源记录重复已自动去重”的承诺。

涉及频率检测的 E3 功能验证保持原时序，吞吐试验单列。客户端的调查正确性以实际可查询数据为准，不把更快回放导致的窗口密度变化当作检测效果提高。

## C. TeleAgent 联调次序与现有证据

| 层次 | 已有依据 | 本迭代要补的验证 |
|---|---|---|
| 本机签名与 API | 2.7.0 独立实例已验证创建、提交、消息、SSE 与取消 | Node.js 适配与实际宿主认证候选、重启恢复；不读取其他会话或整份配置落盘 |
| 真实模型文本 | 已登录桌面后端有一次合成案例真实对话 | 本应用的会话映射、正常终结、错误和多次运行稳定性 |
| 工具调用 | 独立实例使用模拟模型、模拟审查和合成 MCP 已通过 | 真实模型调用本项目工具，核对实际审查链及文本返回兼容 |
| 项目取证 | 尚未验证完整链路 | 工具以受限账号查询 E2/E3，结果进入后续模型分析，引用与实际查询对得上 |
| 按证据改变调查 | 既有模拟链路证明工具结果进入第二轮，不证明真实模型的调查选择 | 同一问题下改变成功认证、冲突或权限条件，观察后续查询、解释或停止原因相应改变 |
| 对话委派与结果回传 | 尚未验证来源识别、独立调查与原对话异步通知 | 发起对话可信绑定；快速工具回执；独立会话取证；结果回到原会话，忙碌、断线和重复投递可恢复 |
| 使用任务收益 | 既有研究不提供此结论 | 在相同数据和权限下比较人工、模板与交互调查流程 |

原依据见[隔离 API/MCP 报告](../reference-index.md#source-04)和[真实桌面文本验证](../reference-index.md#source-03)。本次设计没有重新执行这些探测，也没有获取或保存运行密钥。

专用 Skill、Agent 提示与工具权限的加载路径要有实测记录。不能只把 Skill 放进目录就认定已加载；不能只依赖提示中的步数上限认定工具和费用已受硬限制。模型路由、usage 与真实底层型号分别记录，无法确认的信息不补写。

MCP 需验证：实际协议协商、认证信息传递、合法本地请求的 Origin 处理、跨工作区拒绝、任务上下文建立和失效、只允许选定查询。若使用 HTTP 无法满足绑定，可评估实际受支持的 stdio 隔离；在证明前不开放实时取证工具，也不将匿名本机服务作为完成方案。

委派与取证分别验证：来源会话的身份必须来自可信宿主或独立绑定，不能来自模型参数；调查会话不能调用委派端创建下一任务，发起会话也不能使用调查凭据取任意证据。最小链路先验证父对话收到快速回执后，宿主可运行独立调查且能向正确来源投递，避免直到完成全部界面才发现会话锁、身份或回传能力不可用。

消息追加若用作回传候选，必须验证在 TeleAgent 原对话实际可见、忙碌时安全排队、投递去重和完成回执；不能只凭 API 接受提交就记成功。仅支持 get_investigation_result 的主动取回可以单列通过，但不计为自动异步回传通过。

## D. 首版验收用例

实现阶段为以下情况准备可复现输入和明确预期。这里是验证要求，不表示已经写好或运行测试。

| 类别 | 必须覆盖的情况 | 通过条件 |
|---|---|---|
| 仅提醒模式 | 自动调查关闭，连续送入新告警，TeleAgent 未运行 | 提醒与收件箱正常，没有本客户端发起的自动模型任务；手工入口独立 |
| 无告警主动调查 | 客户端只填写设备、时间、问题；无种子告警；查询零条 | 正常创建请求并查询初始材料，说明覆盖与缺口，不要求造一条告警才能启动 |
| 范围补充 | 主动请求缺设备/时间、设备重名、相对时间、超过范围上限 | 请求留在 awaiting_scope 或返回 needs_input；解析时间与时区可见，补齐后才受理执行，不占活动名额 |
| 三入口一致性 | 相同问题与有效范围分别从告警、客户端、TeleAgent 发起 | 共用请求、调度、案件、证据和预算逻辑，保留不同 origin；结果与来源均可查 |
| TeleAgent 委派 | 原对话提交请求、查看进度，独立调查会话调用取证工具 | 先返回任务回执，来源会话不用一直占用工具调用；子调查能执行且不等待来源结束整个会话 |
| 原对话结果回传 | 原对话空闲/忙碌、多个发起会话、调查失败/取消 | 向正确来源异步投递有身份的结果包；忙碌安全排队，失败或取消也有准确响应；不要求跳转才能看到基本结果 |
| 请求幂等 | MCP 重试、同键同内容、同键不同内容、两个来源复用相同字面键 | 同一来源同请求不重复开任务，内容冲突被拒绝，不同主体或绑定不串任务 |
| 投递恢复 | 结果保存后退出；发送后断线；宿主接受但回执丢失 | 调查不重跑，投递有独立状态；支持去重时安全恢复，不确定时先核实，不反复追加 |
| 回传权限 | 伪造 session_id、指定任意回调地址、来源撤销或账号切换 | 不能改写目的地或取得其他对话结果；绑定失效时停止投递，结果留在原有授权空间 |
| 自动首次调查 | 开启后新增一条符合策略的实时告警；筛选不命中的告警 | 前者无需逐条确认就建案调查，后者仍保留提醒与未触发理由 |
| 历史与开关 | 首次连接有历史；关闭期间收件；重新开启、补收或重启 | 不把历史、暂停期条目和取消任务批量补跑；只接受有效的新触发 |
| 告警风暴与合并 | 同一候选重复读取、短时大量同类告警、多个不同候选 | 重读不重复通知或派发；同案有界合并；不同候选受全局并发和队列限制 |
| 关闭自动调查竞态 | 任务排队、已经领取、已提交模型时关闭 | 旧代次未提交任务不再派发；已提交轮次请求中止并失效工具；提醒继续，已耗用量不抹除 |
| 主动任务与自动开关 | 关闭自动调查后从客户端/TeleAgent 发起；主动任务运行中再切换开关 | 主动任务仍按用户请求执行，不受自动开关取消；共享并发、队列和总用量限制仍有效 |
| 自动预算 | 达到每日尝试数、token 用量未知、重启、跨日、手工任务 | 持久额度不被重启绕过；按配置暂停自动派发；来源与用量分类明确；不宣称硬 token 费用保证 |
| 队列与宿主故障 | 队列满、等待过期、宿主退出或额度耗尽 | 告警与未调查原因仍可见，不丢告警或无限排队；恢复不自动重放全部历史 |
| 同案后续告警 | 初查运行或完成后又来同案记录 | 案件继续更新、旧草案显示覆盖；P0 不无限自动复查，也不隐藏此前可用结果 |
| 窗口与应用退出 | 托盘运行、关闭窗口设置、完全退出或休眠 | 实际驻留状态与说明一致；不把完全退出描述为仍能提供本地提醒 |
| 受限接入 | 面板能用但 API 不通；只有告警权限；部分设备不可见 | 能力与限制准确，仍不要求服务器管理权；不越权补齐 |
| 数据覆盖 | 零匹配、403、超时、分页中断、接口不支持 | 分开表示；部分结果不能显示为完整“无异常” |
| 普通认证背景 | 有告警但没有成功记录权限；已有成功但身份不一致 | 前者列缺口，后者不强行关联；不判“必然没有成功” |
| 清单新鲜度 | 查询成功但扫描时间早；端口只有监听数据 | 显示采集时间与范围，不描述为即时全量状态 |
| FIM 边界 | 有文件变化、无差异正文；路径未受监控 | 不临时读文件，不伪造正文或修改者 |
| 案件组织 | 同 IP 不同主机、同名不同域账号、人工拆案 | 不自动形成确定攻击链，修改可追溯 |
| 分页与重读 | 固定上界多页、重叠重查、页失败后恢复 | 完整批次才推进完成边界；同源引用不重复附案 |
| 动态平台 | 同文档内容更新、迟到记录、源记录过期 | 保存取得时版本与缺口，输入集合可核对 |
| 并发工具预算 | 两次查询并发争用最后额度、超限和超大结果 | 原子预算有效，拒绝或明确部分覆盖，不静默截断 |
| 工具授权 | 错误上下文、另一工作区、过期任务、超范围参数 | 无法取得当前或其他案件材料；模型给出的 ID 不充当权限 |
| 两类 MCP 与递归 | 调查会话请求委派、来源对话调用取证、把回传结果当作新调查指令 | 角色隔离生效；同一请求不重入，完成结果不自动派发下一轮 |
| Agent 分支 | 身份一致的后续成功；只有不一致成功；没有成功日志权限 | 后续查询、解释或停止理由根据实际证据变化；不机械调用全部工具，不把缺权当作未发生 |
| 版本竞态 | 模型运行中人工补证或刷新；旧结果晚到 | 旧结果不覆盖新版本，差异和采纳状态明确 |
| 提交不确定 | 204 但未找到消息；创建或提交后断线 | 通过消息和错误核实，不能盲目重提或报告成功 |
| 取消与恢复 | 客户端重启、宿主退出、SSE 断开、取消未确认 | 映射保留；取消请求与实际终态分开；旧工具上下文关闭 |
| 输出校验 | 非法结构、越界引用、引用存在但结论不受支持 | 前两者程序拦截；最后一种交人工核验，不声称自动证明正确 |
| 注入与界面 | 日志夹带操作指令、脚本、外部图片或恶意链接 | 不新增工具权限，不执行内容，不自动外发或导航 |
| 核查跟进 | 模型报告完成、人工标已处理、没有复核证据 | 任务、审核、案件与处理记录分别保存，不自动认定威胁消失 |
| 客户端完整工作 | 收件箱筛选建案、设备页主动调查、背景录入、步骤与引用查看、修订和导出 | 用户在客户端完成主要任务，无需到 TeleAgent 手工复制提示或结果；模型不可用时人工记录仍可维护 |
| 背景有效性 | 未核实陈述、已核实说明、说明过期或目标/时间不一致 | 使用正确版本并显示来源与适用范围，不把所有说明都当成良性证明 |
| 交互追问 | 活动轮次补充材料；完成后追问依据；要求新取证 | 新材料不暗改冻结输入；已有依据可直接定位，新取证创建可追溯的后续轮次 |
| 初查时间覆盖 | 告警发生后立即启动，请求包含未来五分钟 | 实际上界与未覆盖部分明确，不将尚未发生的时间记为已查无异常 |
| 账号与缓存 | 切换学校账号、撤权、退出、离线旧快照 | 不跨身份复用上下文；离线材料按授权配置展示并注明时间 |
| 实际部署边界 | Wazuh 移到不同主机，客户端无准备目录权限 | 主流程仍经受限接口工作，未依赖本机全知环境 |

接口与业务回归可使用 E1/E2，真实 Agent 调查必须单独给 E4 证据。模拟模型预写的“正确报告”只用于验证数据流，不计入研判准确率。

## E. 使用价值与效果对照

### E.1 比较三种工作方式

| 方式 | 输入与能力 | 主要用途 |
|---|---|---|
| A 现有面板人工核查 | 相同初始告警、数据和权限，由人完成调查与记录 | 了解当前流程和耗时 |
| B 客户端固定模板 | 相同初始告警与获准范围，固定查询、时间线和核查模板，不使用模型 | 分离界面、证据组织带来的收益 |
| C 客户端加 TeleAgent 调查 | 相同初始告警、可用数据和权限，允许有界按需查询 | 检验交互调查的整体收益与成本 |

C 可能查询到与 A/B 不同的材料，因此记录每组实际查询和输入清单，不能把整体收益全部归因于模型推理。若要比较模型解释本身，再以同一冻结证据包比较模板与模型草案。

C 再区分手工启动与自动启动；两者使用相同调查策略时，记录新告警可查询、客户端接收、首次提醒、入队、实际启动和结果可用的时间。自动触发率、预算阻止率、重复调用率、待人工比例与每案用量分开报告，不能只展示成功自动完成的案件。

主动任务再区分客户端入口和 TeleAgent 对话入口。前者记录表单补充、调查查看、核查与导出是否能在客户端完成；后者记录委派回执、原会话收到结果、重复投递和回传失败。区分调查完成时间、原对话投递时间和人工核查时间，不能以子调查完成替代用户实际收到结果。至少保留一个无种子告警的问题。

同一个人反复看到同一案例会学习答案，尽量交错顺序或使用难度相近的不同案例。记录参与者经验、时间、提示、人工帮助与未完成原因；小样本只报告预实验，不宣称普遍收益。

### E.2 评估内容与答案依据

- 需要核查的重要信息是否被找到，来源和采集时间是否正确解释。
- 结论中无依据断言、遗漏冲突证据，以及过早认定良性的情况。
- 完成核查和整理交接记录的时间，使用者实际修改量与复核负担。
- 核查事项是否具体、可执行，处理记录是否保留未解决问题。
- 每案查询次数、传输量、模型与审查等待、可获得的 usage 和失败比例。
- 证据条件变化是否合理改变下一步查询、解释或停止原因；不以“调用过一次 MCP”替代 Agent 调查验证。
- 三入口的完成率、缺项补充次数、单应用完成主要任务的情况，以及来源回传正确率与重复投递情况。

答案使用可核对的底层证据及明确的核查目标。功能边界样本可以有预设结果，但不与公开数据评估混为专业金标。需要安全语义判断的案例尽量独立复核，分歧单列；缺少足够背景时允许“合理结论就是证据不足”。

AIT 攻击阶段覆盖与逐案恶意判断分别报告；模型文字流畅、调用工具次数更多、告警合并数量或报告更长均不作为效果提高的直接指标。

## F. 性能、费用与运行记录

客户端先测真实任务规模，不沿用原 100/500 EPS 作为主要目标。分别记录告警查询、证据保存、会话提交确认、模型与工具运行、校验和人工核查耗时。历史事件发生时间不用于计算客户端阶段耗时。

记录单案数据量、页数、实际查询覆盖、主进程与界面资源、TeleAgent 资源和平台资源。少量调用给出个例和分布，不用不稳定的尾部分位数包装性能结论。超时、取消、不确定与未完成案件保留在分母，并与正常完成耗时分列。

费用使用平台返回的 usage 与可核实单价测算；模型路由别名不当作已确认底层型号。平台内部重试或审查用量不可得时标明不可得，不记为零。本项目字节、工具次数与时间限制不能保证供应商精确费用上限。

一次运行的记录至少包含：代码与依赖、Wazuh 与 TeleAgent 版本、字段映射与 Skill 版本、样本清单、角色范围、能力记录、案件与输入清单、查询摘要、消息映射、校验与人工意见、任务终态及已知缺口。秘密、完整 provider 配置、个人会话和原始请求认证头不进入记录。

## G. 首轮演示与交付

首轮演示采用一个有认证背景的案件，以及一个证据缺失或权限受限的对照。可选再增加已核实授权说明，观察解释变化。至少展示：

1. 项目参考 Wazuh 的部署配置、连接能力与受限范围，平台在独立环境运行，不假定学校已有部署。
2. 关闭自动调查，输入新告警，仅收到本地提醒且无自动模型派发。
3. 开启自动调查并输入符合策略的新告警，客户端自动建案，真实 TeleAgent 接收任务并调用本项目查询工具。
4. 采用两个不同证据分支，展示前一步结果如何改变下一步查询、解释或停止；支持、冲突和未知均可查看。
5. 在客户端从设备和问题发起一次无种子告警调查，查看步骤与证据，补充业务背景、人工修订并导出。
6. 从 TeleAgent 原对话委派独立调查，收到快速回执和最终异步回传；原对话可查看依据、缺口及后续操作，客户端看到同一任务。
7. 关闭自动调查或耗尽测试额度，后续告警仍提醒；主动任务遵守其独立来源和共享限制。复现一次查询或模型故障，任务状态与本地材料仍可用。
8. 复现投递断线/重启或来源会话忙碌，展示独立投递状态、正确目的地及去重/待核实处理，不重新执行调查。

交付包分为客户端与参考平台/实验准备两部分：项目提供 Wazuh 部署和必要配置；客户端不包含实验管理员凭据、原始数据答案或平台数据库。准备说明列出标准配置与用例额外索引、规则或模块，让他人能够复现同等能力；不得把准备环境打包成客户端的隐含运行权限。

最终验收记录逐项写“通过、未通过、未执行、不适用”及依据。只有真实文本对话时不标记工具调查完成；只有模拟链路时不标记真实模型完成；没有现场案例时不标记已经验证高校实际效果。

只有主动取回结果时不标记自动回传完成；只有固定查询和一次报告时不标记已证明证据驱动的调查分支。全部 P0 要求三入口与结果回传均通过，尚未得到宿主支持的链路保留为未通过，不以演示剪辑或人工复制补足。
