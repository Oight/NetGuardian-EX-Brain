## 1. 本版做什么

项目选择 Wazuh 承担参考环境的采集、规则检测、索引与平台展示，并建设面向高校安全运维的调查工作台。应用场景假设存在 Wazuh 或具有类似告警、检索能力的上游；学校尚未部署时，可由项目或部署方搭建参考 Wazuh 环境。首版只实现 Wazuh 适配，类似平台的接入是架构扩展方向，不作为已经兼容的能力。

调查可由新告警、用户在客户端提出的问题、用户在 TeleAgent 对话中的委派发起。客户端统一管理请求、范围、队列、预算、案件、证据和结果；TeleAgent 在专用调查会话中反复执行“提出待验证解释 → 选择查询 → 阅读结果 → 调整解释”，完成后提交草案。使用者可以在客户端完成调查和核查；从 TeleAgent 发起时，在原对话获得进度、结果和后续操作能力。

本版的六项决定：

- **Wazuh 是选定的上游技术栈。** 项目交付参考部署和接入配置；生产环境可接现有平台，也可先部署参考平台。客户端运行账号使用受限接口，平台部署管理与调查运行分工明确。
- **下游建设 Node.js 桌面客户端。** 本版选用 Electron 桌面壳、TypeScript 本地业务核心与轻量 Web 界面，首个验证目标为 Windows x64；这是本版工程选择，业务核心不绑定界面库。
- **TeleAgent 承担 Agent 调查循环。** 客户端经其本机 API 发起专用调查会话；TeleAgent 决定下一项有价值的补证，工具返回后继续分析。客户端以确定性代码执行授权、查询、持久化、调度和校验。
- **三个入口使用同一任务核心。** 告警触发、客户端主动请求、TeleAgent 对话委派都生成 investigation_request；委派 MCP 可以创建任务，取证 MCP 只为当前调查供证，两类权限分开。
- **交互式补证只查询已汇聚的数据。** 不承诺临时读取远端文件、执行命令、抓包或恢复此前未采集的历史。
- **提醒与自动调查分开。** 告警接收、去重、触发判断和提醒由确定性代码完成；自动开关只控制告警驱动任务，客户端与 TeleAgent 中的用户主动调查独立生效。

### 1.1 首版交付范围

| 必做能力 P0 | 完成后使用者能做什么 |
|---|---|
| 连接与能力检查 | 知道账号可查询哪些索引、主机范围和数据类型，以及当前哪些入口不可用 |
| 新告警与提醒 | 应用运行期间接收新增告警、去重并提醒；自动调查关闭或 TeleAgent 不可用时仍可工作 |
| 告警选择与案件组织 | 按时间和设备查告警，选择一条或一组建案，人工修正关联 |
| 主动调查入口 | 在客户端填写问题、设备与时间，也可从设备详情发起；不要求先有一条告警 |
| TeleAgent 对话委派 | 在原对话提交调查、补充范围、查看进度、取得完成结果和请求取消；所有入口共用案件与任务 |
| 可选自动调查 | 开关开启后，符合已配置范围的新告警自动建案和调查；调用、排队与未调查原因可见 |
| 证据工作台 | 查看时间线、源记录、取得时间、采集时间和查询覆盖，不把推断混入观测 |
| 交互式调查 | 查看调查步骤、补证依据和缺口；补充上下文、追问或发起新一轮，通过获准查询形成带引用草案 |
| 设备与业务背景 | 查看获准设备及其数据新鲜度，维护来源明确的部门、用途、重要时段和授权说明 |
| 人工核查跟进 | 修订判断、维护核查事项、记录处理情况、导出交接草稿 |
| 失败与恢复 | 模型、平台或网络不可用时仍保留已取得材料和明确的任务状态 |

P1：证据与报告的自动差异解释、外部资产或业务日历同步、相似历史案件推荐、关键变化触发自动复查、第二种平台适配。P0 包含基本案件检索、手工业务背景、三个调查入口及来源对话结果回传；P1 不进入首版完成条件。

首版不做：自研日志采集与通用解析平台、自研原始攻击检测器、完整 CMDB、全天候无人值守监控、跨电脑共享案件、自动派单或向第三方发消息、自动封禁和平台策略修改。向已绑定的发起 TeleAgent 会话回传所请求的调查结果属于任务响应。Wazuh 原生检测质量与本项目调查增益分别报告。

### 1.2 项目价值与高校场景

主要验证任务是“从一个告警或一个安全运维问题到一份可执行、可追溯的核查记录”。目标使用者暂按学校或院系具有上游平台查询权限的安全运维人员设计，具体角色与核查流程需要用访谈或经授权案例验证。

高校特点通过具体业务背景表达，例如某次实验是否有授权、维护说明是否覆盖目标和时间、案件需要交接给哪个单位。P0 提供关联到设备和时间范围的业务背景卡片，保存来源、有效期和核实状态；用户提供内容默认未核实。平台未提供的信息保留未知，不虚构学校资产、业务日历或负责人。

### 1.3 运行模式与开关

| 模式或状态 | 告警与提醒 | 模型调查 |
|---|---|---|
| 仅提醒，默认 | 在已配置监测范围内持续查询、去重、展示并提供本地通知 | 不自动派发告警调查；用户可在客户端或 TeleAgent 中主动发起 |
| 自动调查开启 | 同样接收与提醒，显示自动建案、等待与调查结果 | 满足触发策略、预算及连接条件后自动启动 |
| 自动调查被暂停 | 接收与提醒继续，显示预算、宿主或队列等暂停原因 | 不派发新的自动任务；恢复后不补跑全部历史 |
| 应用仍在托盘运行 | 沿用当前模式；后台状态明确可见 | 受相同开关和预算约束 |
| 应用完全退出、休眠或离线 | 不保证本地实时提醒，恢复后显示接收缺口 | 不保证继续执行；已提交任务需核实远端状态 |

“关闭自动调查”与“退出应用”是不同操作。窗口关闭是否驻留托盘通过明确设置决定；首版不另外安装常驻系统服务。仅提醒模式不依赖 TeleAgent 登录或可用，也不为提醒内容调用模型润色。这里约束的是本客户端发起的调用，不替 TeleAgent 自身其他后台功能保证零消耗。

首次启用自动调查时配置监测设备、候选规则族或等级及预算，可选择覆盖全部可见告警；不能默认从整个索引历史开始消耗额度。该配置作为持续生效的策略，不要求每条告警再次确认才启动。

### 1.5 从脚本整理到 Agent 调查的变化

| 环节 | 固定脚本加报告生成 | 本版调查方式 |
|---|---|---|
| 起点 | 预先选好的一组告警 | 告警、无告警的运维问题、TeleAgent 对话委派 |
| 取证选择 | 脚本固定查询和字段，全部拼成一个输入 | 初始提供少量种子与能力目录；Agent 根据待验证解释选择工具与查询条件 |
| 中间反馈 | 缺少材料时最终报告统一写缺失 | 读取每次结果与覆盖后，决定继续查询、检验替代解释或因缺证据停止 |
| 调查过程 | 一次请求的输入和最终文字 | 可观察的调查步骤、查询、证据变化、分支理由与停止原因 |
| 输出 | 最终报告 | 可追溯草案、未解决问题、核查事项和返回发起入口的结果 |

例如认证失败聚集：先检查是否存在身份一致的后续成功；发现成功后，再按可用能力查看相关 FIM 或主机背景；只有失败且缺普通认证记录权限时，说明无法验证成功与否。查询路径由实际返回材料决定，禁止要求每个案件机械调用所有工具。客户端不保存或展示模型私有思维链，只保存可供用户核查的步骤摘要、查询理由、工具记录和结论依据。

| 同一使用者电脑 | 用户已有 TeleAgent 桌面宿主及本机 Go 后端 | 使用现有登录与模型路径；本机签名认证桥接待验证 |
| 外部配置环境 | TeleAgent 实际调用的模型与审查服务 | 按实际配置确认接收内容与留存；本地后端不代表全部数据留在本机 |

Wazuh 的 Indexer 与 Server API 职责不同，分别认证与授权；面板能登录不意味着独立客户端一定能调用所需入口。[Wazuh 架构与通信](https://documentation.wazuh.com/current/getting-started/architecture.html)

参考平台的安装、模块启用、规则与只读角色配置属于项目集成交付。平台管理员负责这些准备，日常客户端不持有管理员权限。平台适配层定义 list_capabilities、search_alerts、get_record、可选 search_authentication_events 和清单/检查查询等内部契约，保留原生等级、源身份、时间质量和覆盖信息；它不是直接开放给模型的任意查询接口。第二种平台需要独立字段映射、授权与分页验证，不能只替换 URL 就宣称兼容。

客户端完全退出、休眠或离线时不承诺继续接收、提醒、受理委派或投递结果。上游 Wazuh 独立按其配置工作；客户端恢复后核对接收进度、远端调查会话和待投递结果，再按启动与补收策略工作。原 TeleAgent 对话中的工具请求应明确返回客户端不可用，不声称任务已经受理。多人共享状态与常驻系统服务需要独立设计，不能通过共享本地数据库文件实现。

## 3. 客户端模块与技术选择

采用单仓库、一个本地业务核心。界面、IPC 和 MCP 复用同一查询、案件、证据与校验逻辑，不分别维护业务实现。

| 模块 | 职责 | 明确不承担的职责 |
|---|---|---|
| desktop / preload / ui | 窗口、有限 IPC、连接配置、案件与调查交互 | 不持有 Wazuh 密钥，不运行模型生成的脚本 |
| connections / platforms / wazuh | 上游契约、Wazuh 认证、能力记录、受限查询、字段投影、分页与覆盖 | 不查询任意 URL，不将尚未实现的平台标为兼容 |
| alert_watch / triggers | 运行期间轮询、收件箱、去重、提醒、触发与合并、自动预算 | 不调用模型判断“是否值得调用模型”，不因预算耗尽丢弃告警 |
| requests / scheduler / delivery | 三入口请求、范围确认、幂等、统一队列、预算预占、来源结果投递 | 不靠自然语言中的 session_id 确定回传对象，不无限重试 |
| cases / evidence / context | 案件、不可变证据、查询记录、输入版本、业务背景与人工备注 | 不复制全校原始日志，不伪称原始记录永久可回查 |
| investigations / teleagent | 专用调查配置、本地任务、会话映射、签名请求、消息回读与取消 | 不接管 TeleAgent 账号登录，不假定随包文档全部准确 |
| mcp / delegation | 向获准的发起对话提供请求、状态、结果和取消工具 | 不把来源会话标识当成模型可自选的参数，不直接向平台取任意数据 |
| mcp / evidence | 向专用调查会话提供有限取证、步骤摘要和草案提交能力 | 不创建另一调查，不执行远端命令，不自行扩大范围 |
| reports / followups | 草案校验、人工审核、核查事项与导出 | 不自动认定远端处置生效，不向第三方发送内容 |

技术基线：Electron、TypeScript、Node.js；本地事务存储采用 SQLite；输入输出采用运行时 schema 校验；HTTP 与流读取封装在连接适配器中。具体库与版本在首个可运行验证后锁定，Electron 内嵌 Node 版本、SQLite 驱动和打包兼容性一起核验。本次不把数据库或打包库的选择当作已完成验证。

界面只加载本项目打包资源，关闭 renderer 的 Node 集成，启用上下文隔离与沙箱；preload 只暴露有限业务操作。日志、模型文字与报告作为不可信内容显示，不执行 HTML、脚本或自动加载外部图片。打开链接与导出由用户操作触发。[Electron 安全说明](https://www.electronjs.org/docs/latest/tutorial/security)

平台凭据和 TeleAgent 本机签名凭据仅在本地核心使用。首版默认会话期持有；选择保存时使用系统保护存储，不写入案件、日志或导出。系统保护存储不可用时回退为不保存，不能静默明文保存；这不等于案件数据库已整体加密。[Electron safeStorage](https://www.electronjs.org/docs/latest/api/safe-storage)

## 4. Wazuh 数据能力与访问边界

### 4.1 建立连接时记录的能力

2026-10-21 已对测试环境完成[首轮能力核实](wazuh-capability-assessment-2026-10-21.md)：Wazuh 4.14.9 下，管理员经正常面板登录可查询告警、归档、清单、FIM、漏洞和 SCA；9200 直接连接被拒绝，55000 可用且面板当前用户 token 可访问。软件状态索引为空但 Syscollector API 有数据。该记录用于落实本节的条件能力，不代表受限账号、稳定认证与增量轮询已通过。

每个连接保存平台实例标识、用户身份、实际版本、获准入口、索引模式、可见设备范围、字段映射版本及最近核验时间。能力按“可用、无权、不可达、不支持、未知”分别记录，不用一个布尔值概括。

有效查询范围取平台实际授权与本地案件范围的交集。平台授权由服务端执行，本地限制只是进一步收敛；查询成功不用于反推账号拥有整个学校的数据权限。能力核实使用已有授权的只读请求，不执行写入或越权探测。

| 数据能力 | 用途 | 接入条件与解释限制 |
|---|---|---|
| 告警搜索与详情，P0 必需 | 建案、相关记录、时间线 | 已获准的告警索引与字段；保留源索引和文档身份 |
| 基础认证背景，条件可用 | 查询失败之后是否出现可关联的成功 | 对应记录已采集且可查询；不能从告警缺失推断成功不存在 |
| 主机身份与连接状态，条件可用 | Agent ID、主机名、系统、最近心跳等 | 通过获准资源接口或已有数据取得；不等于业务服务健康 |
| 系统、软件、进程、网络清单，条件可用 | 解释主机背景与潜在暴露面 | 版本、系统、Syscollector 配置和查询权限支持；是带采集时间的清单 |
| 文件完整性信息，条件可用 | 受监控文件的变化与属性 | 仅监控范围内；内容差异、修改者等按实际配置，不提供任意文件读取 |
| 漏洞与配置检查，条件可用 | 已安装软件相关漏洞、已有检查结果 | 需启用相应模块和数据入口；漏洞命中不证明被利用 |
| 未触发告警的普通日志，非默认能力 | 更完整的行为背景 | 需核实归档、索引与授权；服务器上有文件不等于客户端可读 |

告警优先通过 Indexer API 查询；授权的搜索 POST 仍是只读操作，不能用“一律禁止 POST”代替路径和请求体白名单。资产清单在适配版本支持时可经状态索引或 Server API 查询，选择一条已验证路径，避免重复计数。[告警查询](https://documentation.wazuh.com/current/user-manual/indexer-api/use-case.html)、[清单查询](https://documentation.wazuh.com/current/user-manual/capabilities/system-inventory/viewing-system-inventory-data.html)

只读角色与具体资源范围分别核对，不照搬全索引授权示例。若只有面板访问而没有可确认的程序化入口，标记接入前提未满足；不自动使用面板抓取、管理账号或新增服务兜底。[角色与资源范围](https://documentation.wazuh.com/current/user-manual/user-administration/rbac.html)

### 4.2 新鲜度、覆盖与分页

每次查询返回：实际查询条件、可见范围、查询时间、来源观察或扫描时间、返回数量、分页状态、截断及错误。快照缺少采集时间时标为未知，不以查询时间补造“当前状态”。当前官方 Syscollector 示例默认一小时扫描，端口默认仅监听端口；以安装环境实际配置为准。[清单配置](https://documentation.wazuh.com/current/user-manual/capabilities/system-inventory/configuration.html)

告警查询采用固定时间上界、固定排序和该版本支持的分页方式。分页失败保留已取得内容并标记部分完成；只有整批完成后才记录已完成边界。重叠查询以平台实例、索引和文档 ID 去重。若没有可验证的稳定分页或接收时间字段，不承诺连续增量无遗漏，首版使用显式时间窗重查。

“可见范围内未返回匹配”“无权访问”“查询失败”“仅返回部分”“是否采集未知”是不同结果。跨设备比较只覆盖获准设备；只经 Syslog 上报的设备不自动具有原生主机清单能力。全事件归档默认关闭，启用归档也需另外核实可检索路径。[归档说明](https://documentation.wazuh.com/current/user-manual/manager/event-logging.html)

### 4.3 告警接收与本地提醒

本版的“接收告警”默认通过现有获准查询入口进行增量轮询，不假设 Wazuh 主动推送给客户端，也不要求学校服务器新装转发服务。起始周期 10 秒，单连接不重叠发起轮询；错误退避并显示数据更新时间，不承诺严格实时。

接收模块保存 alerts_inbox、已完成查询边界及本地接收序号。平台实例、索引和文档 ID 标识同一告警；重复读取不重复通知、建案或创建调查。每条新记录持久化时同时保存提醒与触发决策；完成该批分页后才推进接收边界。重启后的重读按同一身份幂等处理。

首次连接建立监测起点，既有历史作为预览或历史补收，不自动派发。重新打开应用后先核对缺口，补收与实时新增分别标识；初始只自动补查最近 30 分钟可查询范围，更久历史由用户选择。缺少可信接收时间或稳定分页时，使用重叠时间窗重查并保留覆盖限制，不宣称无遗漏。

提醒由原生等级、主机、规则、时间和数量生成固定模板，本地桌面通知与收件箱共用去重记录。通知可以合并显示告警风暴中的同类条目，但收件箱保留各条记录；提醒静音不修改自动调查开关，也不等于关闭 Wazuh 原告警。

启用自动调查时记录当前接收序号和策略版本，只对启用之后的实时新增记录判定自动触发。历史补收、已读条目、旧队列或重新开启前的告警不因开关变化自动补跑，可由用户另行选择手工调查。

## 5. 用户工作流与界面

### 5.1 一条告警调查流程

1. **连接与设置。** 用户填写获准入口并认证，界面显示可用数据能力；自动调查默认关闭，用户可配置范围和预算后开启。
2. **接收与提醒。** 客户端查询新增告警并持久化，先显示本地提醒；自动调查关闭时到此结束，保留手工入口。
3. **建立案件与范围。** 自动模式按确定性策略形成候选案件；手工模式可选告警，也可直接指定设备、时间与问题。告警调查默认请求前后各五分钟；启动时冻结实际查询上界，晚于启动时间的部分标为尚未覆盖，不等待未来数据后才提醒，也不把它写成已查无异常。设备与时间仍受账号和应用上限约束。
4. **发起调查。** 调度器在发送前核对开关、策略代次、去重、时效与预算，冻结输入并建立 TeleAgent 会话；手工任务保存其明确来源。
5. **按需补证。** Agent 使用已开放工具查询；每次结果记录来源、覆盖和缺口，用户可以补充备注。
6. **形成草案。** 将支持、冲突、未知和建议分开。点击引用查看本地快照，获准时可打开 Wazuh 原记录。
7. **人工核查。** 用户认可、修订或保留未知；创建核查事项、记录处理与复核情况。
8. **保存与导出。** 导出前预览案件范围、依据、缺口、审核状态及待办；P0 导出 Markdown 与 JSON，不自动发送。

自动归并只形成候选调查对象，不等于确认同一攻击链；同一平台、确定目标、规则族和来源限定的主体一致时，才能按已配置短窗合并。关键身份缺失时各自建候选，不把空值或相同 IP 当作公共案件键。用户可以拆案、移除关联并留下修改记录；自动案件保留分组依据和触发来源。首版不建设新的通用原始攻击检测引擎。

### 5.2 自动触发、合并与预算

自动调查由本地确定性策略触发，使用 Wazuh 原生规则族、等级、获准设备和可确认实体；每次记录告警身份、案件、origin=alert_auto、触发理由、policy_version、开关代次与输入版本。用户主动任务分别保存 client_user 或 teleagent_user，不再用一个 manual 值抹平来源。策略过滤只影响自动调查，不把未选中的告警认定为良性或从收件箱删除。

| 情况 | 本地动作 |
|---|---|
| 首次符合策略的新候选 | 先提醒，再进入起始 10 秒合并等待，形成一个待调查任务 |
| 同案重复读取或已有待运行任务 | 前者去重；后者并入最新未运行输入，不反复新建任务 |
| 同案已有活动调查 | 新告警继续入库、更新案件并提醒，当前轮次保留原输入；P0 不并发重开同案调查 |
| 同案已完成一次自动调查 | 后续告警保留并提示新证据；P0 不因每次追加再自动调用，用户可手工复查；关键变化自动复查列 P1 |
| 不同候选同时进入 | 全局并发仍为 1，按已配置原生等级与等待时间排序；手工请求优先但不强制中断正在运行的一轮 |
| 额度耗尽、队列满、等待过期、宿主不可用 | 保留告警与未调查原因，回到提醒；不静默丢弃，不无限积压或自行改用其他模型 |
| 关闭自动调查 | 取消尚未提交的自动任务；已提交自动任务关闭工具上下文并请求中止，显示仍可能已发生的消耗；手工任务不受该开关取消 |
| 重新开启、重启或跨日恢复额度 | 核对持久状态，不自动恢复已取消、过期或历史任务；只接受有效的新触发 |

候选分组设置最大跨度与不活动间隔，避免同一主体长期被并成一个无限案件。首版起始跨度上限 30 分钟、不活动间隔 10 分钟，均为待回放调整的项目配置，不能解释为行业攻击标准。新一组告警形成新候选仍受每日预算约束。

| 自动调查配置 | 首版起始设置与含义 |
|---|---|
| 自动开关 | 默认关闭；范围、预算与暂停原因在同一设置视图可见 |
| 每日自动启动尝试 | 初始 10 次，发送前持久预占；失败、超时及再次提交都占用，不因重启清零 |
| 自动待运行队列 | 与主动请求共用总容量 20 个，自动候选初始等待上限 15 分钟；超限或过期保留待人工查看的原因 |
| 自动重试 | 默认不自动重提未知是否受理或已失败的调查；只读状态核实与平台内部重试另记 |
| 单轮限制 | 继续使用第 7.2 节的查询、工具、数据量与有效期约束 |
| token 观察与停派 | 显示实际可得 usage、估算和未知项；若配置 token 预算，则按已知消耗与预留估算决定是否启动下一轮，未知用量时暂停而非按零计算 |

日期边界采用配置中明确的时区，计数与预算预占持久保存；手工调查单独标记并展示消耗，不悄悄记作自动任务。一次启动可能包含多次底层模型请求，每日尝试数不能解释为模型请求次数。token 估算与停派不保证硬计费上限，正在运行的一轮和平台内部重试仍可能超出估算。

关闭或修改策略推进开关代次。队列领取与发送前均重新校验当前代次并核对预占；已经发出的请求走中止与核实流程，不宣称开关能够撤销已产生的 token。重读、排队合并、结果保存与状态刷新均不能自行触发下一轮。

### 5.3 三个入口与统一请求

| 入口 | 用户或系统给出的内容 | 进入统一核心前的处理 | 结果呈现 |
|---|---|---|---|
| 告警触发 | 告警身份、规则、设备、事件时间、触发策略 | 确定性分组和过滤，形成种子与范围；受自动开关约束 | 收件箱状态、案件、完成提醒与草案 |
| 客户端主动调查 | 问题、平台连接、设备与时间，可选告警或既有案件 | 表单确认范围；缺失项留在待补充状态；不要求先有告警 | 当前工作台中的进度、证据、结果和追问 |
| TeleAgent 对话委派 | 用户问题及工具传入的结构化设备、时间，可选案件 | 绑定真实来源对话，校验范围与幂等；缺项立即返回 needs_input | 原对话先收到任务回执，完成后收到摘要、依据、缺口和任务身份 |

三个入口都创建 investigation_request，至少包含 request_id、origin（alert_auto / client_user / teleagent_user）、principal、connection_id、question、requested_scope、seed_refs、可选 case_id、idempotency_key、created_at、expires_at。系统补充 effective_scope、scope_status、policy_version、origin_binding 和 result_destination；敏感绑定凭据不作为普通业务正文或模型输入。相对时间在受理时解析成绝对时间并记录时区，主动请求初始有效期 15 分钟，界面与工具回执都返回实际到期时间。

无告警调查以问题、范围、能力目录和已知背景启动，初始证据可为空。搜索返回零条时输出本次覆盖和缺口，不能为满足报告格式虚构告警。P0 使用结构化范围控件和确定性身份解析；TeleAgent 发起对话可以帮助用户整理参数，但客户端最终校验。缺失设备、时间或身份歧义时，客户端展示待补充卡片，委派工具返回明确缺项；补齐前不占活动调查名额、不创建调查会话。

同一幂等键与相同规范请求返回同一请求和任务；同键不同内容返回冲突。作用域包含主体与来源绑定，防止不同对话碰撞。一次 MCP 传输重试不会创建新轮次；用户明确要求复查时使用新请求并关联前次结果。不同入口对同一案件的重复调查给出已有活动任务，用户可以订阅其进度；问题或范围不同则另行排队，不静默合并问题。

自动开关只约束 alert_auto。client_user 与 teleagent_user 都属于用户主动请求，不因自动开关关闭而被拒绝，也不消耗每日自动尝试配额；二者仍受共享并发、队列容量、单轮预算、已配置的总用量停派和授权限制。三个入口的待运行总量初始上限 20，主动请求优先于自动任务且不打断活动调查；队列满时明确返回 queue_full，不创建不可见的后台任务。

### 5.4 客户端导航与操作

| 视图 | 主要内容 |
|---|---|
| 总览 | 新告警、待核查案件、运行与排队任务、连接缺口；一键进入“发起调查”和最近工作 |
| 告警收件箱 | 按设备、时间、规则、等级筛选；合并通知、静音、标记已读、选中建案、查看未自动调查原因 |
| 设备与背景 | 获准设备、原生主机信息、清单新鲜度、已有发现；维护业务用途、部门、重要时段与授权说明，从设备发起调查 |
| 调查与案件 | 按状态、时间、设备、问题检索；新建无告警调查、拆分/关联案件，打开工作台、取用来源对话任务 |
| 核查与交接 | 人工判断、核查事项、负责角色、处理与复核记录、报告修订和导出预览 |
| 连接与设置 | 平台入口与当前身份、数据能力、TeleAgent 桥接、自动策略、预算、托盘与留存；显示待验证能力 |

使用者看到“哪些信息还缺、下一步查什么”。查询错误代码、哈希和原始协议等细节放在可展开的诊断与依据视图，不占据主流程。

P0 的总览只汇总本机当前主体可见的告警和任务，不展示虚构的全校风险分数。设备页复用已有数据和手工背景，不建设完整 CMDB。案件基本列表和检索属于 P0，跨案件的智能相似推荐属于 P1。

### 5.5 调查工作台的具体交互

~~~text
问题与范围：设备 / 时间 / 来源入口 / 覆盖到何时 / 当前状态
┌────────────────┬──────────────────┬────────────────┐
│ 证据与时间线    │ 调查过程与交互    │ 草案与核查事项  │
│ 告警、查询结果  │ 步骤摘要与工具状态│ 支持/冲突/未知  │
│ 来源与采集时间  │ 缺失信息提示      │ 引用与审核状态  │
│ 背景与授权说明  │ 补充材料、追问    │ 编辑、采纳、导出│
└────────────────┴──────────────────┴────────────────┘
底部任务栏：排队原因 / 当前消耗 / 停止 / 恢复核实 / 结果回传状态
~~~

界面操作与含义：

- 点击调查步骤可展开调用的工具、过滤条件、返回数量和覆盖；点击引用查看实际交付模型的证据版本。
- 用户可以补充维护说明、确认来源、记录反例；材料作为新版本保存，活动轮次不被静默改写。
- 活动轮次中的普通输入保存为待处理追问，当前轮次结束后提示启动下一轮；用户选择“停止并重新调查”才请求取消并创建后续任务。P0 不承诺已提交轮次可即时插入新提示。
- 完成后追问“这个判断依据是什么”可直接定位报告与引用；需要新取证的问题建立新 analysis_run，保留前后关系与原入口。
- “采纳草案”“修订判断”“完成核查事项”“关闭案件”是分别保存的操作；来源对话收到草案时也保留未审核标记。

用户从客户端进入时，能够在本应用完成范围配置、调查进展查看、追问、证据核验和导出，无需手工切到 TeleAgent 复制提示与结果；TeleAgent 的登录或桥接配置属于首次连接步骤。用户从 TeleAgent 进入时，原对话可完成提交、补充缺项、查状态、取结果、提出后续调查或取消；复杂证据浏览可选择打开客户端，但基本结果不能只返回一个要求跳转的链接。这里的“单个应用”是每个入口都能完成主要任务，不把两个软件的窗口或登录强行嵌成一个。

### 5.6 业务背景与核查的产品功能

业务背景卡片至少保存设备或范围、用途/部门、说明正文、适用时间、来源、录入人和核实状态。相同目标与时间的已核实维护说明可作为解释依据，过期或未核实材料必须明确标记；背景变化使案件输入版本前进。调查前可查看将要使用的背景，调查后可追溯实际使用版本。

核查事项由问题、建议操作、负责角色、状态、截止时间（可空）、人工记录与证据组成。支持筛选未完成事项、标记待他人确认、填写处理说明及复核结果；没有远端观测时只记录人工自述。交接预览包含问题、范围、时间线、事实、分析、缺口、人工结论及未完成项，P0 导出 Markdown/JSON。上述功能即使模型不可用，也能依靠用户已取得材料继续工作。

### 5.7 TeleAgent 对话委派与结果回传

~~~mermaid
sequenceDiagram
    participant U as 用户
    participant O as TeleAgent 发起对话
    participant D as 客户端委派 MCP
    participant C as 统一任务核心
    participant R as TeleAgent 调查会话
    participant E as 客户端取证 MCP
    U->>O: 调查某设备某时间的认证异常
    O->>D: request_investigation（问题、范围、幂等键）
    D->>C: 绑定来源身份并受理
    C-->>O: accepted + request_id + job_id + 范围
    C->>R: 创建专用会话，提交种子与调查 Skill
    loop 按证据需要，受范围与预算约束
        R->>E: 查询相关告警/背景/获准发现
        E-->>R: 证据 ID、实际结果、覆盖与缺口
    end
    R-->>C: 候选报告与引用
    C->>C: 核实终态、封存证据、校验并持久化结果
    C-->>O: 向绑定来源回传结果与投递身份
    O-->>U: 展示摘要、依据、未知与核查建议
~~~

request_investigation 快速返回回执，不把整个调查挂在一个长时间 MCP 调用上。发起对话可以继续处理其他内容；调查会话独立运行，全局“1 个活动调查”只计调查任务，不把正在等待结果的发起对话算进去。来源会话若忙碌，完成通知进入投递队列，不能中断用户的新一轮对话。

结果包包含 request_id、job_id、case_id、run_id、result_version、任务终态、审核状态、调查摘要、带本地证据身份的主要依据、冲突/缺口、核查事项、覆盖范围和可选客户端定位。失败、取消或证据不足也形成相应结果包；“已完成投递”与“调查成功”分别记录。只有同一主体、来源绑定及其获准案件能读取结果。

来源由已认证的宿主桥接提供，记录宿主/账号/工作区/会话及请求消息的绑定；模型参数中的 session_id 不决定路由。已绑定会话以外的地址、会话或任意回调 URL 不作为结果目的地。最小回传内容按来源会话的外发边界裁剪，不自动回传全部原始日志。

**异步回传属于 P0 的联调验收项，目前没有实测证明。** 候选是宿主桥接将结果作为原对话的外部任务结果交付；若实际 API 只能追加消息，需证明原对话可见、忙碌处理、身份校验和不重复展示，不能把给调查会话提交 prompt 的接口直接当成已支持的来源通知。普通 MCP tools/call 的返回只对应当前调用，不自行提供稍后唤醒任意会话的能力。[MCP 工具调用规范](https://modelcontextprotocol.io/specification/2025-06-18/server/tools)

get_investigation_result 是原对话主动取回结果的补充路径：原生异步通知不可用时仍可取结果，但必须显示需要主动查询，不能据此验收“自动回到原对话”完成；也不让发起模型通过无限轮询等待结果。该链路依赖尚未验证的宿主能力，应在大量界面开发前完成最小验证。

### 6.2 证据身份与两种“时间”

证据身份至少包含平台实例、源索引与文档 ID，或资源接口、设备、清单类别与采集标识。相同内容的两次真实行为不能只因文本哈希相同就合并。

证据记录保留 observation_time、retrieved_at 与时间质量。清单是某次扫描的状态，告警是平台规则形成的记录，人工备注是用户陈述，模型报告是分析产物；四者保留不同来源类别。

同一源 ID 再查询内容发生改变时，产生新的本地证据版本。内容哈希用于发现本地内容变化，不证明日志真实、来源未被攻陷或推理正确。原记录过期后，界面仍可显示获准留存的取得时快照，并注明源记录当前不可查。

### 6.3 交互补证如何与冻结输入共存

调查启动时冻结初始证据 E0 和案件 base_revision。工具后续读取实时平台，但每次返回的实际内容先固化到本轮 run_evidence，再交给模型；不能只保存时间窗就声称输入已冻结。

每条工具结果和最终草案都引用本轮已交付模型的证据 ID。调查结束时封存 E0 加补证集合、查询覆盖、工具与提示版本，计算最终输入清单摘要。该清单是本轮实际使用的输入，不保证平台在整段调查期间保持不变。

若案件仍处于 base_revision，在同一事务中并入本轮新证据、推进案件版本，并关联当前草案及其覆盖版本。若用户或刷新已修改案件，本轮结果保存为历史候选，标明“基于旧版本”，不覆盖当前判断；采纳或重新调查由用户决定。无论是否成为当前草案，run_evidence 和本轮结果均可在该历史轮次中按权限查看。

自动接收的新告警也可能使案件版本前进。界面仍可展示最近完成的草案及其明确覆盖范围，并提示尚有新证据未分析，不能因为持续有告警就隐藏所有已有结果，也不能在 P0 中因此不断重启模型调查。

一次调查期间改变设备或时间范围需结束本轮并建立新范围；模型只能提出扩大范围的建议，不能自行解除限制。人工补充材料形成新案件版本，未结束的旧轮次保留其原输入关系。

## 7. 调查工具、Skill 与本地校验

### 7.1 两类 MCP 与首版工具目录

下列是本项目设计的 MCP 工具，不是 Wazuh 或 TeleAgent 原生接口。工具只接受受控业务字段；不接受任意 DSL、SQL、URL、文件路径或系统命令。

**委派 MCP：供发起 TeleAgent 对话调用。**

| 工具 | 输入要点 | 输出与边界 |
|---|---|---|
| list_investigation_scope | 已配对连接、受控设备筛选、分页 | 可用连接与设备的必要标识、可选能力、范围限制；不返回凭据 |
| request_investigation | 问题、连接、设备、时间、可选种子/案件、幂等键 | accepted / needs_input / rejected 及原因；受理时返回请求和任务身份，不等待调查完成 |
| provide_investigation_input | 本来源待补充的 request_id、缺失范围或补充说明 | 补齐后进入统一调度；已经运行的调查只保存后续输入，不改写冻结输入 |
| get_investigation_status | 本来源可访问的 request_id 或 job_id | 阶段、进度摘要、排队/暂停原因、是否有结果；不查询其他来源任务 |
| get_investigation_result | 本来源可访问的任务、可选结果版本 | 有界结果包或尚未完成状态；证据详情仍受对应范围约束 |
| cancel_investigation | 本来源创建且可取消的任务、理由 | 取消请求回执和已观测状态；不能取消其他主体任务 |

客户端 UI 使用同一业务方法。委派端允许用户要求开展调查，但不开放当前调查的取证上下文；来源对话不会直接继承所有案件数据。主动取回结果与订阅完成通知共用授权检查。若多个来源订阅同一任务，普通订阅者取消自己的订阅，不获得取消整个任务的权限。

**取证 MCP：只供客户端创建的专用调查会话调用。**

| 工具 | 输入要点 | 输出与边界 |
|---|---|---|
| get_case_context | 本轮案件上下文标识 | 当前问题、范围、能力、初始证据索引、人工备注及其来源 |
| search_related_alerts | 获准设备子集、范围内时间、选定事件类别或实体 | 有界摘要、证据 ID、查询覆盖与下一页游标 |
| search_authentication_events，可选 | 范围内设备与时间、带命名空间的账号/来源、成功或失败等受控结果 | 经确认的告警或普通认证事件查询路径；保留来源类型与身份匹配质量，无相应采集或权限时不开放 |
| get_evidence | 本轮可访问的证据 ID | 必要详情、源定位、取得和观察时间；不因给出 ID 就跨案件取证 |
| get_host_inventory，可选 | 范围内设备、获准清单类别、受控过滤项 | 最近采集的系统、软件、进程或端口清单及扫描时间 |
| search_file_changes，可选 | 范围内设备与时间、受控匹配项 | 已保存的 FIM 变化，不把路径参数解释为远端读文件 |
| get_host_findings，可选 | 范围内设备、漏洞或配置检查类别 | 已有检查结果、产生时间与覆盖；不触发临时扫描 |
| record_investigation_step | 待验证问题的简短摘要、阶段、下一项查询目的或停止原因、相关证据 ID | 更新用户可见进展；标记为 Agent 声明，不伪装成工具已执行或系统事实 |
| propose_report | 结构化草案、支持与冲突引用、缺口、核查建议 | 保存待校验候选，不改变人工审核、案件解决或 Wazuh 状态 |

可选工具只在能力确认后向 Agent 开放。文本 JSON 放在 MCP content 中；可以另带结构化内容，但不只返回 structuredContent，因为所分析 TeleAgent 适配路径未证明会单独读取它。[本地 MCP 分析](../reference-index.md#source-02)

### 7.2 工具范围与调用预算

MCP 请求由已认证连接关联到有效调查上下文；模型传入的 run_id 只用于一致性校验，不能充当授权。每次执行都检查当前账号、设备与时间子集、有效期、返回量和预算；并发工具也共用原子预算。

委派端与取证端使用不同角色、凭据与可见工具清单，不能只靠工具说明区分。专用调查会话不能调用 request_investigation；即使手写请求到委派端，也应因没有委派角色而被拒绝。普通发起对话不能使用调查会话的 run 凭据读取证据。旧轮次凭据失效后，新轮次使用新的授权上下文，不把一个全局可变“当前案件”挂在共享 MCP 连接上。

来源会话识别和每轮取证隔离都需要可信宿主信息或经验证的独立连接机制。共享 MCP 配置中只有应用级密钥而没有可信会话信息时，不能声称已实现来源对话隔离；由模型传回工作区、session_id 或秘密文本也不能补足该边界。M0 分别验证两种角色，不能以全局单调查代替绑定验证。

首个工程候选采用本机 Streamable HTTP。仅绑定回环地址，验证 Origin（无 Origin 的本地客户端按明确规则处理），使用独立应用凭据，禁用局域网访问。实际 MCP 版本、认证头传递和工作区隔离必须与 TeleAgent 联调，不直接套用最新协议。规范提供的安全要求可参考[版本化传输说明](https://modelcontextprotocol.io/specification/2025-06-18/basic/transports)。

必须证明工具连接能绑定本项目授权上下文，旧任务、其他工作区或无效连接不能使用当前案件。当前研究尚未验证这项绑定；未通过时不启用实时 MCP 补证，只允许明确标识的冻结证据文本验证。不能用“只监听本机”代替认证，也不能凭模型传回 session_id 证明调用来源。

| 初始限制 | 本版起始值，后续按实测调整 |
|---|---|
| 本应用活动调查 | 全局 1 个；其他请求保存为待运行或由用户取消 |
| Wazuh 查询并发 | 最多 2 |
| 每次搜索 | 每页 50 条、最多 4 页；超限标明部分覆盖 |
| 单轮数据范围 | 来自用户请求或已启用的告警策略，首版最长 1 小时、最多 5 个获准设备 |
| 单轮预算 | 最多 12 次取证端工具执行，其中最多 10 次查询/读取；预留至少 2 次供步骤摘要与提交草案；最多 20 次平台请求、300 条不同事件记录（告警及普通认证事件合计），达到查询限制即停止新增取证 |
| 工具返回 | UTF-8 文本最多 16 KiB；大结果先返回摘要、ID 与游标，不静默截断证据 |
| 查询与整轮有效期 | 查询起始超时 10 秒；本轮起始有效期 5 分钟 |

这些是本项目主动设置的实验保护值，不是 Wazuh 或 TeleAgent 官方限制、性能结论或费用硬保证。到期后关闭工具上下文并请求中止；外部模型内部重试和已经产生的费用不能由本地预算完整控制。

每次分页与重试都计平台请求，缓存命中不重复计平台请求但仍计工具执行。进展摘要可以随查询输入一同提交，避免为每次查询增加独立记录调用；专用记录工具与最终草案也占 12 次总额度。查询额度耗尽但尚在有效期内时允许用剩余额度总结；有效期已到则停止工具并中止，已取得的部分材料保存为 needs_review，不假装一定能拿到完整报告。委派工具有独立限流和轮询退避，不消耗子调查的取证调用额度，也不能触发新的模型轮次。

### 7.3 专用 Skill 与输出

安全调查 Skill 固定步骤：确认问题、范围和能力 → 阅读种子或查询初始材料 → 提出待验证解释 → 按需补证 → 核对支持与冲突 → 输出缺口和核查事项。日志与用户导入文本仅作材料，不赋予新增工具权限；用户明确操作通过应用业务核心生效。

首版使用一种专用调查 Agent 配置，按需加载一个调查 Skill。TeleAgent 发起对话是用户入口，不额外建设并行分析团队；每个任务由一个专用调查会话完成。通用 Shell、文件浏览、网络访问、个人记忆写入、委派工具与非项目 MCP 不作为调查轮次能力开放，其实际拒绝行为列入联调。

无种子告警时先阅读问题和范围，再查询初始材料。每次补证之后，Agent 检查结果是否支持现有解释、是否出现冲突、下一项查询能否减少关键未知；可按实际结果改查另一个方向，也可在能力缺失时停止。停止原因至少区分问题已得到有限回答、关键材料不可得、预算耗尽、用户取消、执行失败与需要扩大范围。需要用户解释的授权背景以待核查事项呈现，P0 不让子会话无限等待人工回答。

工具内部只做声明范围内的查询和必要字段映射，不隐式执行一整套调查再把成品交给模型。程序可做确定性时间线排序和身份核对；是否进一步查成功认证、FIM 或主机发现由 Agent 在已公布能力中选择，查询条件与结果均留痕。验收必须证明后一次行为受前一次证据影响，而非只观察到调用过 MCP。

草案包含：案件与本轮引用、调查问题、事实与证据 ID、分析假设、支持与冲突、缺失信息、调查分类、核查建议。调查分类为“需要继续调查、已有解释、证据不足”，属于模型建议；人工结论单独保存为“确认攻击、确认良性、仍未知”。不以模型自报置信度生成处置阈值。

程序校验 schema、枚举、范围、证据是否实际交付本轮、版本与覆盖信息。校验通过只表明格式和引用关系有效；“证据是否支持该断言”单列人工核验，不包装成已实现的自动证明。无效引用、冲突未处理或无结构化结果时，保留文字并显示待复核，不显示为已校验报告。

## 8. TeleAgent 连接与执行生命周期

### 8.1 已有事实与采用方式

本版以 2026-10-18 对 TeleAgent 2.7.0 的本地研究为依据：已登录桌面后端完成过真实文本对话；独立 Go 实例完成过模拟模型、模拟审查与 MCP 工具链。真实模型、专用 Skill、受限工具和实际 Wazuh 的组合尚未验证。[真实对话记录](../reference-index.md#source-03)、[隔离验证记录](../reference-index.md#source-04)

采用“保留已有桌面宿主，调用本机 Go 后端”的接入候选，不直接分发随包 Go 后端，也不接管账号登录。认证桥接是首个实现前置项：端点和凭据由已获授权的宿主接入机制提供；研究中读取配套进程环境取得密钥的做法不作为客户端默认安装机制。当前材料未证明稳定公开的凭据导出接口。

| 操作 | 已研究接口 | 本项目处理 |
|---|---|---|
| 就绪与状态 | GET /ready、GET /session/status | 就绪不代表已认证或模型可用；不把其他会话信息写入案件 |
| 新建 | POST /session | 保存返回的真实 ID 与一致工作目录 |
| 提交 | POST /session/{id}/prompt_async | 204 仅记提交响应，继续核实本次消息 |
| 进度 | GET /event | 过滤当前会话，作为交互进展，不单独作为完成依据 |
| 核实结果 | GET /session/{id}/message | 匹配本次用户消息与对应助手 parentID、完成字段、finish 和 error |
| 取消 | POST /session/{id}/abort | 记录已请求中止与实际观察的终态，不用本地按钮证明远端已停 |
| 来源对话识别与结果通知 | 尚无对应项目链路实测 | 需要可信来源绑定和可核实的投递接口；不从既有 prompt_async 测试推导此能力 |

适配器按已编码的最终路径和查询串签名，重试使用新时间戳与 nonce；不硬编码研究时的端口、模型路由或 Agent 名。业务 job_id 独立于后端生成的 messageID。GET /agent 在所测样本返回 404，不将随包 OpenAPI 当作完整实测能力表。

宿主连接适配设计为提供“取得端点、对规范请求签名、返回宿主与账号身份、绑定发起会话、向绑定会话投递结果及取得回执、重新连接”六项能力；签名凭据不交给界面或模型。实验启动器可在隔离实例中供应自己生成的本地密钥，以测试协议适配；已有桌面的凭据来源、会话身份获取和结果投递必须另外验证。该契约用于隔离接入问题，不宣称宿主已经提供对应公开接口。

### 8.2 会话、任务与恢复

每轮 analysis_run 使用新 TeleAgent 会话，客户端自己维护案件中的连续对话与已审核背景；不跨案件复用会话，也不依赖个人长期记忆保留案件。跨轮复用历史结论时标明其审核状态和覆盖版本，不能将旧推断直接升级为事实。

保存 request_id → case_id → run_id → investigation_session_id → user_message_id → result_message_id 映射，另存 origin_binding 与 origin_request_message_id。发起对话与调查会话是两个不同身份，不能因二者都属于 TeleAgent 就混用工具、消息或取消目标。需在 M0 验证同一宿主能在发起对话返回委派回执后运行独立调查会话，不因会话锁或全局限制形成等待死锁。

请求状态与执行状态分别维护：请求为 awaiting_scope / accepted / rejected / withdrawn；只有范围完整且受理成功的请求才关联待运行任务。accepted 不代表模型已经执行，调查成功也不代表来源对话已经收到结果。

| 本地任务阶段 | 完成或恢复规则 |
|---|---|
| coalescing / queued | 自动候选先有界合并，主动请求直接排队；关闭自动开关或策略变化只取消旧代次自动任务，所有来源均检查范围、过期与用量 |
| preparing | 固化范围、初始证据、预算与连接身份，尚未发外部请求 |
| submitting | 记录发送意图和尝试；创建或提交结果不确定时转 uncertain，不自动重提 |
| running | 已确认本轮用户消息，跟踪进展与工具；SSE 断线先回读消息 |
| verifying | 关联正常完成的助手消息，关闭工具上下文，封存输入清单并校验草案 |
| succeeded / needs_review / failed | 分别表达可用草案、需人工处理、执行失败；均保留实际依据与错误 |
| cancel_requested / cancelled / uncertain | 区分已请求停止、已观察到取消、仍无法确认；不无条件重开重复任务 |

应用重启先读取未完成映射，只查询本应用记录的会话与消息；核对宿主、工作区和账号是否仍匹配。无法确认旧任务时显示待核实，用户可放弃本地轮次，但工具上下文立即失效，远端是否仍运行单独说明。后续新轮次使用新的上下文，旧请求不能获得新案件数据。

自动开关按连接主体保存，重启可恢复用户已选模式，但必须先核对身份、数据能力与持久预算，之后仅处理有效的新触发。身份变化不沿用另一主体的自动策略。关闭自动调查后，提醒与接收游标继续推进，不把暂停期间记录留成等待下一次开启补跑的模型任务。client_user 和 teleagent_user 任务使用各自的明确取消操作，不能被自动开关误取消。

启动时尚未提交的旧自动队列统一转为待人工查看，不自动补派。已经提交的旧自动任务只做状态核实；开关仍关闭时继续执行中止流程，开关开启时也不以新提交代替恢复。这样接收补查、模型任务恢复与新的自动触发分别处理。

未提交的主动任务在重启后显示待恢复，用户可在原入口或客户端选择继续；通过身份、来源绑定、范围、时效和预算核验后才提交。已提交的主动任务先核实原会话，不因自动开关关闭而中止，也不重新创建一份调查。来源对话关闭不自动证明调查取消，明确取消请求才进入中止流程。

退出前，用户可等待或请求取消运行任务。休眠、网络中断与宿主退出不等于供应商未执行；恢复后先核实，不能以连接失败为理由无限重试。平台可能自行重试，客户端记录自身尝试与已取得 usage，不声称掌握每次底层请求或精确费用。

### 8.3 结果投递、幂等与恢复

调查结果在本地校验并保存的同一事务中写入待投递记录，事务提交后才调用宿主。投递键由 origin_binding、request_id、run_id 与 result_version 确定；从 UI、状态查询和通知触达同一结果不会再次创建调查。

投递状态为 pending / sending / delivered / uncertain / retryable_failed / blocked。宿主接受请求、消息实际可见与用户已读是不同事实；只有获得可核实的接收消息身份或宿主等价回执才记 delivered，不声称用户已读。宿主支持幂等时按其契约重试；发送后断线但可能已写入时记 uncertain，先核实，不能无限追加相同结果。宿主不支持去重且无法核实时，显示待确认并保留主动取回路径。

投递前复核账号、工作区、来源会话绑定、数据外发范围与结果权限。身份变化、会话失效或绑定撤销则暂停回传，不把结果发到另一个活跃对话。结果回传失败不改变已经保存的调查终态；客户端继续可见。恢复只重试已核实安全的投递，不重新调用模型生成同一报告。审核后的新结果可形成新 result_version，并明确“人工修订”，不暗中替换已经送出的版本。

原对话接收的内容标记为外部调查结果和对应 request_id，不作为新的用户调查指令；来源 Agent 不因该结果再次调用 request_investigation。除非用户明确追问并产生新请求，不能形成“委派 → 回传 → 自动再委派”的循环。模型提示中的规则之外，专用调查角色缺少委派权限，并以请求幂等、来源事件类型和任务父子关系阻止同一请求重入。

### 8.4 模型上下文与外发材料

只发送字段白名单内的案件摘要、必要证据与明确问题，不发送 Wazuh 凭据、完整平台配置或整个日志目录。原始完整快照可留本地，发送给模型的是本轮被选择的必要内容，选择与省略均记录。

已知真实文本测试中，简短案例仍记录一万以上输入 token，包含通用主 Agent 提示等开销；专用配置的成本必须重新实测。TeleAgent 的个人记忆与项目指令加载需核对，关闭记忆整理不等于旧记忆不注入。未确认独立上下文和外发范围前，联调仅使用合成或公开样本，不承诺真实学校数据的隔离效果。[循环分析](../reference-index.md#source-05)、[提示词与记忆](../reference-index.md#source-06)

平台数据的读取授权与向模型、审查服务发送材料的使用边界分别记录。按实际配置列出处理与留存位置，应用本地删除不宣称同步删除 TeleAgent 历史或远端数据。

TeleAgent 原对话可能已有其他材料与个人记忆；来源对话只获得按其权限裁剪的结果，不被当成专用调查的干净上下文。用户主动委派授权客户端完成该调查并回传该绑定对话，不能据此向其他会话或服务发送内容。

## 9. 人工核查、排序与本地数据

案件状态为待确认、调查中、已解决、重新打开；任务状态按第 8 节；草案审核为未审核、已采纳、有修订、已否定。报告完成不自动解决案件；用户记录已处理不自动构成远端动作回执。

核查事项包含要核实的问题、建议步骤、负责角色（可未知）、状态、人工记录与证据。P0 在本地保存、导出并按请求回传绑定发起会话，不接入真实工单系统、不自动通知他人。用户关闭案件时保存理由和未解决项，不要求用模型分类替代人工结论。

调查排序优先显示原生告警等级与等待时间，用户可调整并记录理由。若有来源明确、时效有效的业务重要性，可提供辅助排序；缺少该信息就显示未知。拟处置建议依据已取得事实与人工核实提出，不自动写回 Wazuh 或降低原生告警等级。

本地空间按平台实例与登录主体区分。切换身份不复用旧查询游标、活跃任务与缓存；退出后锁定该空间。离线查看和证据留存按授权配置执行，离线内容均显示取得时间且不能刷新。撤权不能靠旧缓存延续新的查询或补证。

应用提供证据留存上限、案件清理和导出预览，默认不建立全量镜像；上限按实测大小设置。证据到期清理后保留引用缺口与必要业务记录，不继续显示“引用可核验”。本地访问限制不等于能抵御同一操作系统账号的恶意程序，也不宣称数据库具备取证级防篡改能力。

## 10. 一个可验证的首版案例

以下是待实验验证的示例，不是已有成果：实验室服务器产生认证失败聚集告警。客户端首先提醒；如果自动调查已开启且该告警符合策略、预算可用，就自行建立限定该服务器和相邻时间的候选案件，调查是否需要优先核查账号使用。仅提醒模式下，由用户选择相同告警手工启动。

| 步骤 | 应用与助手行为 | 可核验产物 |
|---|---|---|
| 接收与建案 | 去重、提醒；按自动策略或用户操作保存告警及范围，不重新发明失败次数 | 原规则、平台引用、触发来源与初始快照 |
| 补证 | 若认证背景可用，查询是否有可关联成功；否则明确缺口 | 查询范围、实际返回与覆盖说明 |
| 背景 | 若清单与 FIM 可用，查看最近快照和相邻变化 | 扫描时间、文件变化；不宣称登录造成该变化 |
| 解释 | 提出运维重试或账号滥用等待检验解释 | 支持、冲突、未知及引用 |
| 人工核查 | 用户记录维护说明，标明来源与是否已确认 | 人工意见及其案件版本 |
| 跟进 | 生成需要确认的会话活动、授权情况等核查事项 | 可编辑清单、处理记录和交接草稿 |

在相同告警下分别使用“没有维护说明”和“存在覆盖相同目标及时间、已核实的维护说明”的材料，检查解释是否合理变化。授权说明不自动消除冲突证据；只有用户陈述时不写成已经证明良性。

同一实验还要从另外两个入口完成：

- **客户端主动调查：** 用户从设备页选择实验室服务器和最近 30 分钟，输入“近期认证异常是否需要优先核查”。即使没有种子告警也能启动；Agent 先检索初始材料，再根据实际证据选择后续查询，用户在工作台查看结果、补充维护说明并发起复查。
- **TeleAgent 对话委派：** 用户在原对话提出相同问题，来源 Agent 调用委派 MCP；客户端创建独立调查会话，该会话用取证 MCP 查询。任务完成后结果回到最初对话，用户能查看依据、缺口或请求后续调查；工作台保存同一任务，不要求人工复制报告。

为证明 Agent 调查发生了相应变化，准备“出现身份一致的成功记录”和“没有成功记录权限”的两个分支：前者应围绕成功后的活动选择进一步证据，后者应说明缺口并停止该方向或转向其他可验证问题。不能预先把整套调查结果塞入初始提示，再用一次工具调用装作完成交互调查。

| 里程碑 | 实施内容 | 通过条件 |
|---|---|---|
| M0 接入可行性 | 参考 Wazuh 部署与受限查询；TeleAgent 认证、专用上下文、两类 MCP 角色绑定、发起对话身份与结果投递 | 最小样例证明来源对话可委派独立调查并收到可核实结果；形成实际接口记录，未通过项不能包装成完成 |

| M2 TeleAgent 文本轮次 | 会话映射、签名、提交、消息核实、取消和恢复 | 真实合成案例完成；204、断线、错误状态处理正确 |

| M4 三入口与工作台验收 | 自动策略与持久预算、客户端主动调查、对话委派、结果投递恢复、交互工作台与核查交接 | 三入口使用同一任务与证据核心；两个应用入口各自完成主要任务；重试、取消、关闭、权限、重启与回传竞态符合约定 |
| M5 可选扩展 | 自动证据差异、外部业务上下文同步、相似历史推荐、关键变化自动复查、第二平台适配 | 按价值验证和剩余工作量选择，不挤占 P0 修复 |

不继承七天或 84 人时的交付承诺。M0 后根据实际接入难度、开发人数与 M1 原型记录重新估算。硬件先满足两个桌面应用和小样本调查，分别测量客户端、TeleAgent 与实验 Wazuh；不把原 32 GB 平台预算当作每位使用者的已证实要求。

实现交付包括：客户端代码及锁文件、可运行安装包、Wazuh 参考部署与模块/角色配置、平台适配契约及字段映射、权限与接口事实表、两类 MCP 契约、专用调查 Skill、脱敏配置模板、三入口与回传样例、验证报告、部署操作说明和已知限制。仅交付本设计不表示这些实现已经完成。

首版完成需另一位成员按说明复现：从参考 Wazuh 的新告警收到提醒并可选自动调查；在客户端不选告警主动提出问题并完成取证、核查与导出；在 TeleAgent 原对话委派后由独立调查会话使用工具，结果自动回到正确的发起对话。三个入口共享任务状态、案件和证据，至少一次展示取证结果改变调查路径，并复现预算耗尽、取消或故障恢复。只有文本联通时标为 M2 完成；只能主动查结果而不能异步回传时，不能验收全部 P0。

## 12. 验证、版本变化与尚未确认事项

验证分为四层：受限接口与数据覆盖、客户端业务正确性、TeleAgent 真实工具链、使用任务收益。平台日志检测吞吐单独报告，不作为客户端成绩。实验数据与标签、完整性检查、对照和演示见[实验与验收附录](security-triage-client-experiments-v4.md)。

相较 v3：Wazuh 及数据准备作为参考平台单独部署；Python 服务改为 Node.js 本地业务核心；单次模型调用改为本地 TeleAgent 会话与有限 MCP；主交付由三源三规则转为告警调查、证据工作台和核查跟进。保留版本、引用、失败可见与人工确认；不继承“客户端掌握所有背景”或全天候运行假设。

相较 v4.0：新告警接收、本地提醒和可选自动首次调查由 P1 或手工入口提升为 P0；只在应用实际运行期间生效。自动初查不等于自动处置，也不承诺每个后续告警都再次调用模型。

相较 v4.1：将 Wazuh 从“学校既有前提”修正为项目选定的参考上游，交付相应部署配置；重写调查过程，明确 Agent 按证据决定下一步；增加无告警主动调查、TeleAgent 对话委派和来源结果投递；将设备业务背景、基本案件检索、调查步骤和核查操作落实为客户端 P0 功能。委派入口可以创建任务，调查取证端仍禁止递归派发。

| 尚未确认 | 对应限制 |
|---|---|
| 实际 Wazuh 版本、入口与角色 | 基础查询需实测；清单、FIM、漏洞、配置检查按能力启用 |
