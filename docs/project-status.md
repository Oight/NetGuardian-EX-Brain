## 当前项目方向

“校安智脑”面向高校安全运维，建设以 Wazuh 为首个上游的安全调查工作台。Wazuh 提供已汇聚的数据和原生检测；Node.js/Electron 客户端统一管理请求、案件、证据、背景、预算与人工核查；TeleAgent 在专用会话中根据证据选择后续查询，形成可追溯的调查草案。

三个入口为告警触发、客户端主动调查、TeleAgent 对话委派。委派 MCP 可以登记调查，取证 MCP 为当前调查提供受限材料；二者使用不同角色和授权。结果需保存到客户端，并按可信来源绑定回传最初的 TeleAgent 对话。

主设计将本地提醒与可选自动调查分开，自动开关不取消用户主动请求；首版只查询已汇聚的数据，保留证据覆盖、失败和未知状态。首版不承担自研采集检测平台、自动封禁、平台策略修改或跨电脑共享案件。

Wazuh 是选定的参考技术栈，不代表学校已部署；类似平台是后续适配方向。10 月 21 日讨论稿记录上游技术方案已冻结，缺口由客户端显示并登记接入条件，不能据此启动新的上游选型。

## 2026-10-22 后续：独立 Wazuh API 接入重试

已形成 [模块与 API 文档核对清单](proposals/wazuh-upstream-access-checklist-2026-10-22.md)。用户明确客户端直接使用 API，不安装或嵌入 Dashboard，也不以面板登录、内部代理或面板 token 作为运行依赖。

用户授权使用指定本地凭据重试；最初受限环境返回本地 `WinError 10013`。用户随后临时启用 full access，独立连接实测为：同一主机 9200 返回连接拒绝（`WinError 10061`），未进入账号验证；55000 HTTPS 可达，经精确目标的实验性证书例外后，用所给账号认证返回 HTTP 401，未取得 JWT 或平台业务数据。详见 [脱敏结果与解释](reference-index.md#source-25)。

随后用户提供 Server 专用账号，独立认证返回 200 并取得 JWT，设备列表与单个可见终端的 OS/硬件/软件/进程/端口、FIM 对象和 SCA 查询均成功，见 [本次成功记录](reference-index.md#source-23)。抽样条目来源时间跨越多个日期，不能统一标为实时状态；本次仍采用目标限定证书例外。

用户再提供 Indexer 专用身份及入口后，直接告警/归档查询与字段投影成功，固定 24 小时告警聚合返回当前账号可见的 3,117 条；根信息、漏洞和两类清单状态请求为 403，见 [Indexer 实测记录](reference-index.md#source-24)。这次使用新文件的完整入口，与旧默认地址探测分别留证；清单可以沿用已通过的 Server API 路径。

两类 API 现均有基础业务读取依据，不再将“未取得 Server/Indexer 账号与入口”列为整体阻塞。剩余接入项是严格证书信任、实际设备/索引授权范围、连续分页、认证失效和字段/来源覆盖；漏洞功能需要单列当前 403 的权限条件。上述成功未证明全设备覆盖或真实模型/MCP 闭环；10 月 21 日管理员经面板取得的数据观察仍按原范围引用。

该提案仍为讨论稿。调查档案、版本对照和局部重查应先做样例与对照，再决定是否进入正式基线；具体依赖版本、驱动、MCP 传输、宿主身份获取和通知机制仍需验证。不得把候选收益写成既有实验成绩。
