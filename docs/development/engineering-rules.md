# Agent工程实现约定

日期：2026-10-23；规范版本0.1。[边界设计](../implementation/boundaries.md) · [贡献流程](../../CONTRIBUTING.md)。

## 1. 代码与契约

采用设计约定的单仓库、TypeScript strict、ES modules和@campussec包名。依赖版本通过基座实际小验证锁定；不写未经验证的兼容版本。默认不加依赖，确需新增时说明用途、范围和打包影响，由依赖任务更新声明/锁。

产品contracts为唯一类型及runtime schema来源，模块不得各存同名副本。内部DTO camelCase，SQL snake_case，UTC带毫秒，scope半开区间。请求未知键/枚举拒绝，上游先白名单映射；秘密只传SecretRef。

## 2. 依赖与数据

只从包公开入口导入，Repository/internal组件不跨包导出。按architecture.json区分S09通道组件与入口，不因同属S09就允许业务反向调用。S06/S10保持设计的下层边界；S07应用组件也分别注入所需窄端口。

同事务回调同步、失败整体回滚，不在事务内await。跨表所有者调用InTx，禁止私写他表；只读聚合须有明确视图契约。单一事实记录与版本CAS优先，不另建一份可随意选择的JSON状态。

S07独占任务终态，S08规范化宿主事实，S10校验报告，S11维护投递。报告完成不自动关案；accepted不等执行，delivered不等已读；uncertain不按失败盲重提。

## 3. 验证与共享fake

基座提供真实contracts、FakeClock/Id、可脚本化HTTP/执行/投递fake和标准向量。fake要模拟外部已执行但响应丢失、权限、partial、过期、取消晚到和版本变化；不能只提供成功数组。

模块测试覆盖自身独有风险，集成测试逐步使用真实模块替换fake；类型检查、运行时schema、SQL约束和业务验收分别记录。中央关键验收场景修改须说明原因并审查，不能实现与预期同时改成同一个错误答案。

检查未提供、依赖缺失、未执行、失败分别报告；禁空脚本/无断言检查冒充成功。默认CI仅合成材料，真实模型/平台证据单列。

## 4. 文件与诊断

UTF-8中文文档，新增维护链接用相对路径；不全仓格式化归档/研究原件。代码日志只保存必要trace、受控错误、计数和耗时，不记录请求正文、认证头、provider完整配置或个人会话。

依赖安装产物、构建缓存、数据库、运行日志和秘密不进入提交。导出和远端访问遵守用户范围；模型文字按不可信数据处理，不执行脚本或自动外链。

## 5. 验收层级

分别标设计静态、合成业务、模拟模型/MCP、真实模型文本、专用账号只读、真实受控工具、三入口/异步投递。一个层级通过不推导下层或上层通过。可用性缺口保持unverified/unavailable，不换成成功fake来满足P0。
