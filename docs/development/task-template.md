# 轻量任务模板

复制到 [tasks](tasks/README.md) 并填写具体内容；占位未填或依赖未落地时保持 planned。PR 和独立复核按需使用。

## 任务与基准

- 任务 ID/标题、完成者：待填写。
- 唯一状态位置：本任务文件；如迁往 Issue，写明链接及切换时间。
- 状态：planned。
- 分支/实际 base commit：待填写，不能写“最新”。
- 版本：业务 v4.2；工程 0.2.0；外部协议 0.1.0。
- 需求文档、依赖提交及已合并状态：待填写。

## 范围与验收

- 用户触发及完成后的可观察行为：待填写。
- 允许修改的确切目录/文件/测试/夹具：待填写。
- 共享只读文件、跨模块依赖、真实/fake/unavailable 模式：待填写。
- 契约/SQL/根依赖变更及消费者、兼容影响：待填写；无则写无。
- 关键失败/竞态场景、实际检查命令及组合验收：待填写。
- 外部操作：默认无；需要时记录当次目标、范围和已有授权。
- 完成条件：行为满足、检查证据、依赖与组合检查通过并进入 main；未执行项不得勾通过。

## 自检与交接

- 实际修改路径、完成行为、检查命令/环境/结果及证据层级：待填写。
- 未执行、失败、阻塞和下一步：待填写。
- base/已合并提交、未提交内容：待填写。
- PR 或他人复核及处理：按需记录，没有则写未使用。

## 多阶段工作线补充

若为工作线任务，另填：工作线 A/B/C/D、分支入口、已核对设计 base 与实际启动 commit、逐阶段状态/前置 commit/允许路径/交付物。只将依赖已具备的阶段置 ready；其他阶段保持 planned。首个离线阶段 ready 不表示整条产品线可实现。每次阶段合并后更新自己的任务文件，不维护第二份状态表。现有四线入口见[任务登记](tasks/README.md)。
