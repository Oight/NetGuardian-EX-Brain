## 放行顺序与合并

1. 四线首阶段可同时开始。A 先交 A1/A2/A3，B/C/D 不重复搭建正式 workspace、公共契约或共享 fake。
2. 基座合并后 B 实现存储/案件，C 实现 Wazuh/宿主/通道，D 实现基于 DesktopApi 的界面。
3. B2 与 C2 的窄端口先交付，A4 用 fake 逐步替换真实实现；C3 再消费 A4，避免整模块相互等待。D2 接入真实案件持久化。
4. B3/C4/D3 与 A5 分阶段完成三入口和恢复组合验收。真实 M0/M3/M4 保持独立证据和当次授权。

各线短阶段分支自检后合并，不等待整条工作线完成。共享变更按[文件归属](../ownership.md)串行处理；没有固定集成负责人或强制他人审批。
