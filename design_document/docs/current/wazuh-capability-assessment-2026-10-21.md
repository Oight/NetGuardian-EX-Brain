测试环境已经提供主机侧告警、非告警归档事件、Linux/Windows 主机信息、软件/进程/端口清单、文件完整性资料、漏洞发现和配置检查结果，可以据此设计主机侧取证工具与客户端页面。**防火墙等网络安全设备来源尚未验证，不能据此认定已满足项目预想的多来源接入。** 后续补查见第 7 节。

2026-10-21 当次观察到的接入限制是：**面板账号不能直接用相同用户名密码登录 Server API；Indexer 的 9200 端口从当次测试端连接被拒绝。** 当次成功查询主要经过已认证 Dashboard 内部接口；另已证明当次登录身份取得的临时 token 可以直接访问 Server API。内部接口可用于该次核实，但其版本兼容性与受限角色行为尚未验证，不自动成为产品的稳定认证方案。

## 4. 对调查设计的直接影响

### 4.1 告警与普通事件应分别检索

当前环境已经允许查看大量没有形成告警的归档记录，`search_authentication_events` 可设计为查询告警与获准归档的受控认证视图，而不是只检索告警。字段映射至少保留平台、设备、账号及其身份范围、来源、事件时间、解码器与原记录定位；本轮仅验证了部分字段，账号关联准确性仍要用带答案的样例核对。

抽样一条告警，以平台记录 `id + agent.id + timestamp` 在归档中查询，找到一条匹配记录。这证明本样本在两个索引族中有重叠，告警数和归档数不能直接相加为独立行为数。客户端保留每个源引用，再用经验证的逻辑事件身份建立关联；单次样本不证明该组合在所有设备、重放和实例中永久唯一。

### 4.2 工具按数据类型选择来源

| 工具或客户端操作 | 本环境可以使用的数据路径 | 首版应明确的输出 |
|---|---|---|
| 告警接收 / `search_related_alerts` | 告警索引 | 原生规则/等级、源 ID、事件时间、实际查询覆盖 |
| `search_authentication_events` | 获准告警与 archives | 成功/失败来源、账号与设备范围、匹配质量和未覆盖项 |
| 设备页 / `get_host_inventory` | `/agents`、Syscollector API，或已验证状态索引 | 数据来源、scan.time、字段缺失；每类选择一种主路径 |
| `search_file_changes` | 告警/归档 FIM 事件 | 实际变化记录；对象状态另列，不把当前清单冒充变化历史 |
| `get_host_findings` | 漏洞状态索引、SCA 策略与检查 API | 发现或检查结果、产生/扫描时间、解释限制 |

来源选择不能只由“哪个接口最近返回 200”决定，需为选定环境固定映射并核对语义。尤其不能把空的软件状态索引当作工具不可用，也不能把 Syscollector 和 Indexer 的计数差直接认定为丢数据。

### 4.3 新鲜度与时间解释进入主界面

抽样结果：Linux `001` OS 的 `scan.time` 为 `2026-10-21T02:38:40Z`，Windows `003` 为 `2026-10-21T03:18:04Z`；相应软件抽样记录为 `2026-10-16`。同一设备、不同类别和条目的来源时间可能不同，不能给整台设备统一标记“刚刚更新”。

本次状态索引的定向时间字段检查没有找到可以直接替代 Syscollector `scan.time` 的通用采集时间。该结论只覆盖所查字段模式；没有证明任何可能的时间字段都不存在。找不到来源时间时应保留未知。

告警 `timestamp` 示例使用 `-0400`，同时存在等价的 UTC `@timestamp`；客户端按明确字段映射转换为同一时刻显示，不按字符串直接比较，也不凭 Manager 的 UTC 时区重解释已有偏移量。

## 5. 接入方案与待完成验证

**建议把当前环境的数据能力纳入设计，接入方式继续作为 M0 工作。** 可以比较以下两种方案：

1. 由部署方提供受限的 Indexer 查询入口与 Server API 授权，客户端通过已公布接口工作。9200 可以是受控网络中的入口，也可以是经过明确部署配置的查询网关，不要求直接暴露到公网。
2. 明确接受固定版本的 Dashboard 适配器，使用其正常登录与受控查询。必须单列内部接口的版本依赖、每用户授权、令牌更新和失效行为；不得将 Console 任意 DSL 或代理任意路径开放给模型。

本轮只证明管理员在该版本下可以走通相应查询与当前用户 token 路径，不替两种方案预先宣布稳定或已完成。没有创建账号、改变角色、开放端口、修改模块、触发扫描/响应或操作测试主机。

后续按以下顺序推进：

- **确定运行账号与查询入口。** 由测试环境维护者提供或配置专用受限账号，再验证账号实际可见设备和数据；管理员成功不能替代此项。
- **验证连续查询。** 固定时间上界、可靠排序/分页、迟到事件、重读去重和断线恢复尚未验证；当前搜索成功不能作为无遗漏轮询的证明。
- **准备一个带答案的调查案例。** 现有数据足以验证接口；成功/失败认证、授权背景和 FIM 因果关系仍需受控样例。当前没有看到特定失败记录，不等于本环境无法支持该案例。
- **确认清单覆盖。** 对比软件/进程/端口的 API 与状态索引，明确首版实际采用路径及来源时间，不要求先把所有索引补满。
- **再接 TeleAgent。** 将这些已验证查询封装成受控取证工具，检查真实模型是否根据证据选择下一步；本轮没有执行模型调用。

python scripts/wazuh_readonly_probe.py --test-certificate
python scripts/wazuh_capability_audit.py --test-certificate --inventory

脚本从本机 `wazuh_passwd.txt` 读取凭据，不要求将密码放进命令行。`--test-certificate` 是指定实验目标的进程内例外；details 脚本为本次已知实验目标显式使用相同例外，生产客户端不能照搬为默认设置。报告中的内部路由只用于环境核实，所有代理的实际操作均为 GET 查询；POST 仅承载正常认证或只读查询。原始日志正文与令牌不进入输出。

## 7. 网络安全设备来源：相对预想范围的缺口

补查时间：2026-10-21 北京时间约 12:18。依据：[来源登记：来源聚合与 remote 配置的选定字段](../reference-index.md#source-12)。这是后续快照，数据量与首轮核实不同；告警和归档共同搜索存在事件重叠，不将聚合总数作为独立行为数。

本次补查结果：

- 当前可见告警与归档的 decoder、规则组、location 和程序名聚合均没有遗漏桶（sum_other_doc_count=0）。未见可确认的防火墙、Suricata IDS 或 WAF 来源特征。
- 这些字段主要指向 Windows EventChannel、Linux auditd/journald/认证、Syscollector、FIM、漏洞与配置检查。当前 JSON decoder 对应的来源均为 vulnerability-detector，不能将其当作已接入任意厂商 JSON 日志的证明。
- 有 Squid 程序的 journald 记录，但没有对应已解码的设备事件或安全规则组；不能据此验收防火墙日志或代理访问审计已接通。
- 只读查询 Manager 的 `remote` 配置，仅返回 `connection=secure`、`port=1514`、`protocol=tcp` 的入口，没有 `connection=syslog`。这只证明本次查询返回的配置，不排除另外的 Syslog 中转机、文件接入或尚未识别的原文。

因此，当前状态应写作：**主机来源已具备数据，网络安全设备来源的接入与可调查性仍未验证。** 四个在线 Agent 的列表本身不能证明是否存在网络安全设备，因为只转发 Syslog 的设备不一定表现为独立 Wazuh Agent。

下一阶段需补齐一个选定来源，优先围绕预想的防火墙场景，而不是一次宣称兼容所有设备：

| 环节 | 需要核实的产物 |
|---|---|
| 真实格式来源 | 明确产品/版本及日志类型；来自获准实机、虚拟设备或出处清楚的样本 |
| 日志进入平台 | 记录实际使用的 Syslog、文件或其他接入路径；通过受控样例证明送达与可检索 |
| 解码与字段语义 | 保留设备身份、事件时间、源/目标地址和端口、协议、动作、规则/签名、原生严重性等实际提供字段；按对应类型验证，不伪造缺失项 |
| 客户端身份与范围 | 将采集 Agent/中转机、产生日志的安全设备、通信参与者分别记录；不能把 Manager 的 000 或中转 Agent 当成防火墙身份 |
| 调查与对照案例 | 选一个可复现的设备事件，能够与同时间的目标主机材料核对；阻断记录不自动证明入侵成功，也不能仅凭同 IP 强行关联 |

Wazuh 可以配置 Syslog 接入，也有 Suricata IDS 的官方集成说明；这些属于可采用的接入能力，不能代替本环境实际完成集成的证据。[remote 配置](https://documentation.wazuh.com/current/user-manual/reference/ossec-conf/remote.html)、[Suricata 集成](https://documentation.wazuh.com/current/proof-of-concept-guide/integrate-network-ids-suricata.html)

回放真实格式样本可以验证格式和查询；实机或虚拟设备实际产生日志并送达，才能验证对应在线接入链路，两者分别报告。当前 v4.2 主图保留了“主机与安全设备日志”，但首版范围和实验验收未把这一来源具体化；主机客户端的定位调整不能解释为已经完成或无需验证网络侧来源。
