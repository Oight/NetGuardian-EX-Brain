状态日期：2026-10-23。初始项目设计和研究资料由 **Shimakaze-17900** 提供并署名，本文由 Codex 辅助整理。来源及共享范围见[来源登记](reference-index.md)。本文区分仓库内产物、提供者的历史记录和仍待取得的验收证据。

## 项目方向

“校安智脑”面向高校安全运维，以 Wazuh 为首个上游，建设 Node.js/Electron 安全调查工作台。客户端管理请求、案件、证据、预算和人工核查；TeleAgent 在专用调查会话中按证据选择后续查询，形成可追溯草案。

告警触发、客户端主动调查、TeleAgent 对话委派三个入口共用任务核心。委派 MCP 与取证 MCP 的角色和授权分开；结果按可信来源绑定返回发起对话。

业务基线仍为 [v4.2](current/security-triage-client-design-v4.md)，内部工程契约为 [0.2.0](implementation/README.md)，外部信封为 0.1.0。首版查询已汇聚数据，保留失败、未知和覆盖缺口；上游选型及部署不在本轮维护范围。

## 候选与后续验证

独立 Node 业务进程、调查档案、版本对照和局部重查仍为[讨论稿](proposals/security-triage-client-detail-proposal.md)中的候选，不自动进入已确认的 P0 完成条件。

| 顺序 | 待验证事项 | 应取得的依据 |
|---|---|---|
| M0 | 宿主认证、专用工具通道、可信来源及结果回传 | 来源对话能委派独立调查并收到可核实结果 |
| M0 | Wazuh 受限接入 | 实际运行账号的稳定路径、授权、分页与覆盖记录 |
| M1—M2 | 客户端与文本轮次 | 可运行安装包、本地持久化、取消/恢复、无宿主时保留材料 |
| M3—M4 | 真实工具调查及三个入口 | 实际材料改变后续查询；角色隔离、正确投递和竞态验收 |
| 实验准备 | 样本、标签和人工参考答案 | 明确规模、来源、权限变体与可复现依据 |
| 项目信息 | 比赛规则与校内使用流程 | 正式规则、截止时间、评分要求及访谈或授权案例 |

正式比赛规则和独立完整会议纪要尚未入库，不从讨论稿推定已获批准的额外范围。新证据由提供者补充共享材料、署名和复核方式后更新；历史实验授权不延续为后续外部操作授权。
