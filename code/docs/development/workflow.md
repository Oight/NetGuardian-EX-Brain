# 多人协作流程

1. 从[任务入口](tasks/README.md)进入本线，读取阶段依赖、允许路径和模块 AGENTS。前置未合并时只做允许的离线工作，不复制邻模块。
2. 产品 Git 基准建立后采用一条 main、短阶段分支、独立工作目录。本目录尚无产品 Git base，本次不创建或推送远端，不编造合并 commit。
3. 每线只更新自己的任务与允许路径。根配置/依赖/接口/fake 的差异交 A 串行处理；物理迁移交 B。
4. 执行[实际检查](commands.md)，核对文件范围和受影响组合。不可用能力报明确错误，不返回成功占位。
5. 交接记录实际 base、依赖 commit、公开入口、失败行为、环境、结果和未执行项。只有真实实现提交合并 main 后才标 done；PR/他人复核按需。

任务状态只在具体任务文件维护。旧基座任务已归档；目录说明与 README 不维护第二份实时进度表。共享契约、迁移、根配置和锁同一时刻只有明确的一个任务写入。

同步事务、跨所有者 InTx、S07 唯一终态、S09 独立通道、S10 不读任务私表等边界保持不变。真实平台、宿主、模型、凭据与远端操作需要对应授权；编译和 fake 不等于真实验收。

## 交接模板

```text
任务/阶段、执行者和日期：
实际产品 base、依赖合并 commit（没有则说明）：
允许路径和实际修改文件：
公开入口、消费示例、兼容影响：
完成行为、关键失败与竞态：
命令、环境、通过/失败/未执行：
未实现、未提交和下一步：
实现/合并 commit（实际存在后补记）：
```
