# 多人协作流程

1. 按拟认领路径从[任务入口](tasks/README.md)选择相关任务，读取阶段依赖与模块说明；原 A/B/C/D 分工仅作参考，共享规则见[仓库贡献约定](../../../CONTRIBUTING.md)。缺少真实依赖时先做可独立实现与验证的部分，明确其余边界。
2. 当前整个仓库共用一条 main；既有产品成果为 64443ed。采用短阶段分支、独立工作目录，产品命令在 code/ 执行。开始前记录实际 HEAD 和依赖合并 commit，不再将导入前“尚无 Git”描述当作当前状态。
3. 每次任务声明主要目录与附带共享文件，在相关任务单记录范围和结果；可跨原工作线串行完成，同一文件同时只交一个任务写入。
4. 执行[实际检查](commands.md)，核对文件范围和受影响组合。不可用能力报明确错误，不返回成功占位。
5. 交接记录实际 base、依赖 commit、公开入口、失败行为、环境、结果和未执行项。只有真实实现提交合并 main 后才标 done；PR/他人复核按需。

任务状态只在具体任务文件维护。旧基座任务已归档；目录说明与 README 不维护第二份实时进度表。共享契约、迁移、根配置和锁同一时刻只有明确的一个任务写入。

远端更新先 fetch 后比较，再选择快进或合并；具体命令、冲突处理和退出方式见[手动同步说明](git-sync.md)。

同步事务、跨所有者 InTx、S07 唯一终态、S09 独立通道、S10 不读任务私表等边界保持不变。真实平台、宿主、模型、凭据与远端操作需要对应授权；编译和 fake 不等于真实验收。

