只读来源 `a06b9a5`，本地实现 `/home/eight/Project/GPT/netguardian/code`。原设计仓库和 campusguard-mui 未修改；没有读取真实凭据或访问真实 Wazuh、模型、TeleAgent。冻结附件检查继续通过。原维护审计迁移移动为 0004，来源 0003 保留 run mapping。

## 运行

本机使用 Bun，先运行检查以生成构建产物：

```sh
cd /home/eight/Project/GPT/netguardian/code
bun scripts/local/check.ts
bun scripts/product/start-web.ts
```

打开终端输出的 `http://127.0.0.1:4180`。首次创建管理员，之后可在“账号与角色”创建分析员或只读账号。各账号使用独立空间。没有默认生产账号或密码。

本地合成网页验收：

```sh
bun run web:qa
```

打开 `http://127.0.0.1:4181/qa/` 和 `/qa/flows`。这是独立的合成入口，包含新建测试账号、受控宿主和代理响应，不能当作真实研判演示。退出终端停止服务并清理临时数据库。

实际部署中，只有在单独获准访问既有代理后才启用：

```sh
bun scripts/product/start-web.ts --campus-proxy
```

该入口固定调用已运行的 `campusguard-mui` 本机 4173 API，不读取/复制该项目的环境文件；不会自行启动该服务或真实宿主。每个新账号空间由可信启动装配建立默认只读代理连接。网页不提供其他直接上游网络入口。

加密数据位于 `.local/web-runtime/auth/` 与 `.local/web-runtime/spaces/<spaceId>/state.ngdb`，凭据和导出另行加密。不要提交这些文件、密钥或运行日志。丢失密码不能绕过解密；旧 `state.sqlite` 不自动迁移；单空间密文快照内的明文数据上限为 64 MiB。详见 [实现增量](../../../design_document/docs/implementation/web-auth-2026-10-24.md)。

## Windows 开发者执行

以下命令仅供有 Node.js 24.15.0、npm 11.12.1 和 Windows 图形会话的开发者，本机不执行：

```powershell
cd <工程目录>\code
npm.cmd run test:windows:full
```

现有一键入口执行冻结安装/检查/干净副本和真实 Electron 双进程验收。脚本新增：未登录拒绝、合成管理员登录、重启登录读回、系统保护外层、加密数据库与秘密存储；报告要求这些项均实际成功。结果写入忽略的 `.local/windows-full/` 和 `.local/electron-acceptance/`。

可另行启动 `npm.cmd run web`；获准代理环境中桌面启动使用 `npm.cmd run desktop -- --campus-proxy`。不要把 Bun 通过记录成 Node.js、Electron 或 Windows 通过。签名安装包、安装/卸载与真实平台/宿主联调仍需另行执行。
